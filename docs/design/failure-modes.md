# Failure modes the code must survive

The project's shared checklist. `/plan` names the entries an issue must
handle; the adversarial reviewers (`.claude/agents/`) go through the ones
that apply to a change. Every entry was learned on this project or its
predecessors. **Add an entry** whenever a review confirms a failure whose
category is not here: an id, what happens, and how to check.

## Vendor DLLs and Micro-Manager adapters

- **FM-01 Prints while loading.** An adapter writes to stdout or stderr, with or without a newline. Any protocol over stdout breaks. *Check*: results travel through a file or a dedicated channel, never "the last line of stdout".
- **FM-02 Crashes or hangs while loading, or at unload.** A result already produced is lost when the parent trusts the exit code. *Check*: adapter work runs in a child; the child writes its result before teardown and calls `os._exit(0)` after the final write; the parent reads the result whatever the exit code.
- **FM-03 A crash dialog (Windows, macOS).** On Windows, a missing dependency or the crash reporter opens a modal dialog, which looks like a hang. On macOS, a crashing `Python.app` (Homebrew) makes ReportCrash show "Python quit unexpectedly" once per crash, `pytest` runs included (#47). *Check*: processes that load adapters guard themselves first: `SetErrorMode(SEM_FAILCRITICALERRORS | SEM_NOGPFAULTERRORBOX)` on Windows, and on macOS libc `_exit` as the raw handler of the crash signals (`_mm_child._no_error_dialogs`). A reproduction that crashes a native process on macOS goes through the same guard, or says in its evidence that it will open a dialog.
- **FM-04 Helper processes inherit the pipes.** The pipe never reaches end-of-file; on Windows `subprocess.run(timeout=…)` then waits without limit after `kill()`. *Check*: child output goes to files; `Popen.wait(timeout)` then `kill()`.
- **FM-05 Non-UTF-8 strings.** pymmcore decodes with `surrogateescape`; one lone surrogate makes the JSON invalid. *Check*: strings from adapters are sanitised before they are serialised.
- **FM-06 Listing devices contacts the hardware.** `NikonTi2` asks the Nikon SDK, and a stand accepts one connection at a time (NIS-Elements, ZEN, a second core). *Check*: the default test suite never lists vendor adapters; surveys run with the vendor software closed.
- **FM-07 Hub-based adapters.** Peripherals appear only after the hub initialises (`getInstalledDevices`). *Check*: probe and configuration code asks the initialised hub.
- **FM-08 Pre-init properties.** Serial devices need `Port` before `initializeDevice`; failing without it is not a hardware fault. *Check*: detect it and report "needs a port".
- **FM-09 One message, many causes.** "Failed to load device adapter" hides missing DLL, wrong SDK, wrong bitness and interface mismatch. *Check*: ask the OS (`ctypes.WinDLL`, WinError code) when the diagnosis matters, in a child process (FM-95).
- **FM-95 A loader probe in a process that already holds the DLL.** Windows resolves a module that the process has already loaded by its base name, so a second `ctypes.WinDLL` probe in the same process can pass while the adapter's own dependency is missing: `nikon-control` probes the vendor DLL first and then the adapter in one process, so the second answer cannot be trusted (from the loader's documented behaviour; not reproduced). The same process also holds the vendor DLL for good, and a `DllMain` that crashes or hangs takes the caller with it (FM-02). *Check*: one child process per probed DLL, started as the adapter children are (FM-04, FM-22, FM-33, FM-35, FM-83), and the parent never loads a vendor DLL; a probe with no verdict (a hang, a crash, no such file, not Windows) is "not probed", never "will not load"; a test replaces the child's command by a canned script, since no test may load a real DLL (FM-40).
- **FM-105 A clean row for what was not tested.** A probe reported `ok` for a hub whose 14 peripherals it never loaded (`SequenceTester`: one device listed, 14 reported after the hub initialises; the Ti2-E: `Ti2-E__0 ok`, no peripherals, `Notes (0)`, #126), read an empty device list as a clean one, and gave a serial device that has no `Port` yet a verdict of its own: `ok` or a hardware fault, when nobody had set the port (#48). *Check*: every row says what was tried; what was not tried is `not-probed` with a `reason`, never `ok` and never `failed`, and the report prints three words (`ok`, `FAILED`, `not probed`); a device the adapter lists and its hub does not report, and one whose pre-init `Port` is empty or `Undefined` and was not given one, have no `loadDevice` or `initializeDevice` in the core's call log; an empty list or a hub that reports nothing is an `error` that carries the stand's meaning; `ProbedDevice.ok` is a property, so no serialised `ok` key can read as a pass.
- **FM-106 A partial result that reads as a whole.** A result file written once, at the end, loses a long probe to a crash (the Ti-E's `TIDiaLamp` has crashed Micro-Manager, so seventeen good rows would go with it); one rewritten after every device reads as complete if nothing marks it, and a reader takes the rows it finds for the whole adapter (#48). *Check*: the walk calls a checkpoint with a deep copy, `complete=False`, once before the first device and after every row, and only the value it returns is `complete=True`; the child's checkpoint writes the file and survives an `OSError` (Windows antivirus, FM-24) as a line on stderr, never as the end of the probe, and swallows nothing else; the parent keeps the partial probe whatever the exit code; the report's title says `INCOMPLETE` for `complete=False`; the crash test finds `probe` not `None` and not complete. The last checkpoint holds the rows, not the `error`, the notes and the `complete` that come after the last one, so the child writes the whole result *before* it releases the probe's core (an unload can hang or crash, FM-02: written after it, a probe that had finished read INCOMPLETE and lost its error, adversarial review of #48), and `_write` waits and retries `os.replace` on `PermissionError`, since the final write is the one nothing else repeats (FM-24); a test records what the result file holds at the moment the core is released, and another holds the replace twice.

## Micro-Manager core

- **FM-10 Timeout shorter than the move.** MMCore's 5 s default is shorter than a plate traverse. *Check*: `setTimeoutMs` from the profile (60 s).
- **FM-11 Device-interface mismatch.** An MMStudio install and pymmcore-plus with different device-interface versions: a `.cfg` from one fails silently in the other. *Check*: report both versions.
- **FM-76 An extra search directory replaces what it holds.** MMCore takes each adapter from the first search directory that has its file, and does not fall back to the next one when that file fails to load. A profile's `adapter_search_paths` (the MMStudio folder) therefore supplies *every* adapter it holds, so one device-interface mismatch (FM-11) fails the whole stand, not only the adapter that was missing (#77). *Check*: a failed load names the directories in the order they were searched, and the setup doc says so; a test stands in for the failing load. A remedy that the tool prints after such a check names the folder of the adapter MMCore takes, not the install's: `smc install-driver ti2` without `--to` copied the driver beside an adapter the profile did not load, exited 0, and left `doctor` saying the same thing; the advice now carries `--to "<that folder>"`, and a test puts the profile's folder before the install's (adversarial review of #12).
- **FM-79 A device fault outside the error taxonomy.** MMCore reports a device fault (a serial timeout on a read, a camera timeout on a snap, an unplugged cable) as a bare `RuntimeError`. Left alone, it reaches the CLI as `✗ unexpected RuntimeError … file an issue`, so the operator files a bug instead of checking the device, and a tool that catches `HardwareError` misses it (#93, found in the review of #89). The translation has its own trap: `HardwareError` *is* a `RuntimeError`, so a handler that catches `RuntimeError` without letting `HardwareError` pass first wraps a `SafetyRefusedError`, or the emergency stop's `MicroscopeHaltedError` raised by a callback inside a command, into a fault. *Check*: one place in the backend turns a core call's `RuntimeError` into a `HardwareError` that names the role and the call, chained `from exc`; every `HardwareError` and every non-`RuntimeError` passes untouched; a test makes the core raise (`FakeCore.failing`, or a patched method of the demo core; patching a capability's own method bypasses the layer and proves nothing), and another raises a `SafetyRefusedError` from inside a core call and finds it unchanged.
- **FM-12 Moving Z switches PFS off** on the Nikon stands. *Check*: suspend and re-engage around Z moves, and re-engage only after a move that completed (FM-88, design m2 §3.4).
- **FM-13 Several devices share a type.** Ti2: four `XYStage` devices, three of them TIRF positioners; Ti-E: three `Stage` devices. *Check*: type-first resolution with exclusions, and the candidates reported.
- **FM-87 A call that acts on a core slot, not on a label.** MMCore's continuous-focus calls (`enableContinuousFocus`, `isContinuousFocusLocked`, `setAutoFocusOffset`, `fullFocus`) and its camera calls take no label: they act on the device that the core's slot names. A role resolved to another device (a profile's `[roles.assign]`, a configuration without `Core,AutoFocus`) then switches or reads the slot's device while the layer reports the role's. With the slot empty, `enableContinuousFocus(True)` raises `Auto-focus focus device not defined.` (measured on the demo, 2026-10-16, plan of #13). *Check*: the facade points the slot at the role once, and every slot call first checks that the slot still names the role's label and refuses otherwise, as `MMCamera` does; a test assigns the role to a second device and finds the slot moved, then changes the slot behind the layer and finds the call refused.
- **FM-92 A reference cycle keeps the core alive until the cyclic collector.** A capability that holds the facade (or another capability that holds it) strongly, that stores a bound method of itself (`SafeCall(send=self._send_off)`), or whose call leaves an object and its callback pointing at each other (`_ZStop.link` and the lambda that `linked_stop` registers, made by every Z move with PFS on), makes a cycle through the core: dropping the facade frees nothing, and the `CMMCorePlus` is destroyed by the cyclic collector at a moment nobody chose, at the exit of a command during interpreter finalization. Up to Python 3.13 a thread still inside MMCore (its 21 pool threads, measured) then takes the process down: `smc doctor`'s child aborted with `FATAL: exception not rethrown` on `ubuntu-latest, py3.10` and timed out on `macos-latest, py3.13` after #140 (#142; the abort itself was not reproduced, the cause was). *Check*: capabilities reach their siblings through a weak reference to the facade, and refuse with a `HardwareError` once it is gone, never with `None`, which reads as "no such device" (FM-12); nothing a capability stores is a bound method of that capability; an object that a call creates and a callback it registers do not refer to each other once the call has returned; `test_a_dropped_facade_frees_its_core_without_the_cyclic_collector` builds every capability, runs each thing the stand does once (a Z move with PFS on, a locked `focus_by_um`, a direct `engage()`, `set_offset_native` and `offset_by_native` with PFS on) under `gc.disable()`, and finds the facade and the core dead; a new capability or a new compound goes into `_use_the_stand`. A cycle that only a call makes passed the test that only built (#142's review). The operator's Z stop path frees too (#163): after a Z stop inside any autofocus compound (the relock, a locked `focus_by_um`, a direct `engage()`, `set_offset_native` or `offset_by_native`, a stop once it has locked again, a stop before the relock's block, a stop that reached a block which ended meanwhile), with a switch-off that succeeds, fails, or fails after the compound stopped waiting for it, or with Z's own stop failing, on Python 3.10 to 3.13, the facade and the core are freed by reference count; `test_a_z_stopped_autofocus_compound_frees_its_core_without_the_cyclic_collector` and its neighbours in `test_mm_autofocus.py` pin it, and the closing edges were FM-98's. One cycle is left, by decision: a lock wait given up whose switch-off failed stays registered, so the stand refuses until `resume()`, and its `Motion` (`stop`, `is_busy`) holds the autofocus, which holds the `Executor`. The facade is freed; the core only once `stop()` and `resume()` succeed or the cyclic collector runs, and `smc.cli.main()` collects after every command (#148). The stand is already in a fault state that asks the operator to act, and breaking the cycle would take weak callbacks in `Motion`, a change to the registry's contract (`lock-wait-given-up` in `test_error_exits_free_the_core.py`). A log call never passes an exception as an argument, only its text (`exc_info=True` counts; `%r` of an exception becomes `%s` of `repr(exc)`, #166; the text is then built by the caller, where `logging` used to swallow a failing `__repr__`, so a path that must not raise guards it: `_send_safe`'s `_repr_of`, `_named`): a kept record (caplog, a GUI log pane) keeps the traceback and the core through it (#158). A test that drops a core and finds it alive: look first for a `LogRecord` kept by pytest whose arguments hold it (pymmcore-plus logs `Initialized core %s` at DEBUG), then for a cycle (`gc.DEBUG_SAVEALL`).
- **FM-99 An API that merges where the caller meant to replace.** MMCore's `defineConfig` changes or adds one setting of a preset and keeps the others, and it accepts the label of a device that is not loaded without a word (measured on the demo, 2026-10-19, m2 §8.1). A capture that redefines a preset of the same name therefore keeps every stale setting the new one does not name: `nikon-control`'s did, and the next `setConfig` then fails on the ghost device or applies the old one (plan of #14). *Check*: delete before defining, and validate what the API does not (the device is loaded, the value fits the file it goes into); a test defines the preset with an extra setting first and finds it gone after the capture, and the mutant that drops the delete is killed. The replacement is then whole, so it says what it dropped: recapturing the lab's `BF` loses its shutter states and its exposure, and a WARNING names each setting dropped and added (adversarial review of #14). A read over every preset skips one that names a device that is not loaded, rather than failing on it (FM-19).
- **FM-100 A match by string on a value the device reformats.** MMCore stores a number it is given in its own format: a preset's `Camera,Exposure,10`, once applied, reads `10.0000`, and `getCurrentConfig`, which compares strings, then names no preset at all (measured on the demo, 2026-10-19). The Ti2-E's `BF` sets `Exposure` 10 and `Intensity` 210, so MMCore would report no current channel right after selecting it (m2 §8.1). *Check*: compare numbers as numbers (equal strings, or two finite floats that are equal; `nan` never matches), never with `getCurrentConfig`; a test applies a preset written `10`, finds the device reading `10.0000`, and finds the preset current; the mutant that compares strings is killed.
- **FM-104 A vendor core's derived value that passes an invalid input through.** MMCore's `getPixelSizeUm()` divides its pixel-size preset by the magnification factor and passes an invalid factor on: a factor of 0 reads infinity, -1.5 reads -0.667, NaN reads NaN (measured on the demo's optovar, 2026-10-20). Infinity is above 0, so a check of `value > 0` alone reported it as a measured pixel size (#167). *Check*: `math.isfinite` on every number the core returns before it is used or compared, both the derived value and the input the layer divides or multiplies by; a test with 0, a negative number, NaN and infinity for each, asserting the whole warning (FM-45); the mutant that drops the finiteness check is killed.
- **FM-14 Turret moves can crash an objective** under a loaded plate. *Check*: turret moves require confirmation.
- **FM-15 A blocking device call under the microscope lock.** A vendor call with no timeout of its own (`snapImage`, a driver deadlock) holds the one `Executor` lock, so every other capability on that stand hangs with no diagnosis (#5 review). *Check*: waits poll `deviceBusy` against a deadline; callers of a lock held too long fail with `MicroscopeBusyError`, which names the holder (design §13); a call with no timeout of its own says so in its docstring.
- **FM-16 A wait that holds the lock.** Polling a moving device while holding the microscope lock blocks every reader and every stop for the length of the move, which is 60 s for a plate traverse (#54). *Check*: reads and the safe calls (stop, closing a shutter) never take the lock, and another caller's action is refused at once while the holder waits for a motion (design §13, revised after #59); a test reads, stops and closes the shutter from another thread while a move waits.
- **FM-17 A wait that gives up leaves the device moving.** A timeout, a Ctrl-C or any other exception during the wait raises, but the stage keeps going while the caller believes the move failed (#52 review). *Check*: every exit from a wait other than "idle" sends the device's stop first; so does a command that raises.
- **FM-18 A stop that races a command.** A stop that does not wait for the lock can reach the device just before a move command already under way, which then starts the stage after the stop (#54). *Check*: a stop that arrives while a command is being sent is sent again after it, and the move raises `MotionStoppedError`.
- **FM-19 A busy state that cannot be read.** `deviceBusy` raises. Reading that as idle lets the next action run during a move; reading it as moving forever locks the stand. *Check*: unreadable counts as moving, the refusal names the error, and a stop or `resume()` releases it; a motion that cannot be stopped (a `State` device) must still have a way out (#59 review). The same holds for any state read before acting: a read that only decides whether to add a safeguard (linking the Z stop to an offset move) counts unknown as the state that adds it, with a WARNING that says so; a read that decides what moves (Z or the offset in `focus_by_um`) refuses (#158).
- **FM-88 A restore step that moves after a failure.** A sequence that puts something back after its main step (re-engaging an autofocus after a Z move, returning to a start position) is itself a motion. Run from a `finally`, it moves the stand after the operator's stop, a halt, a timeout or a fault: re-engaging PFS drives Z (design m2 §3.4, plan of #13). *Check*: the restore runs only when the main step returned normally; on any exception it is skipped, a WARNING says what was left as it is, and the exception propagates; a test stops, halts and faults the main step in turn and finds no restore call in the fake's log.
- **FM-90 A move through another device skips the guards of the axis it moves.** `focus_by_um` with PFS locked changes focus through the PFS offset, and PFS then drives Z by the same distance; the offset's own guards are in its own units and optional, so the Z soft limits, which no Z move may pass even forced, did not apply: a 30 µm change at Z 99 went through where `move_by_um(30)` was refused at a limit of 100 (adversarial review of #13). The fix sat in `focus_by_um` only, and a locked `offset_by_native(30.0)` still drove Z 30 µm past the limit (review of #140). *Check*: every call that moves an axis indirectly, the low-level ones included, checks that axis's guards on the estimated target before it sends anything, not forceable where the direct move's are not; where the conversion is unknown, its docstring says that only the indirect device's own guards apply; a test sets the axis's limit just past the start and finds each indirect call refused with an empty log. When an unforceable guard and a forceable one would both refuse **at the same point** (both before the lock, or both on the same reading inside the action), the unforceable one runs first: named second, it would meet a `force=True` that the first refusal invited (#158). A guard that needs no reading (a jog) still runs before anything is read, so that a refused jog takes no lock and reads nothing; a target refused after it (a relative target, read inside the action) names itself, and cannot be forced either (#166).
- **FM-117 A stop the device refuses.** On the Ti2-E, `core.stop()` raises `Unsupported device command (11)` for `XYStage`, `ZDrive` and `PFSOffset`, idle or moving, and a move that was sent runs to its target: a Ctrl-C during a 20000 µm jog was logged as "stop failed", then printed as "any move under way was stopped", and the stage went all the way (Ti2-E session 1, #208; #204, #206). FM-17's "send the stop first" protects nothing there. *Check*: every message after a stop says what the stop's outcome was (accepted, refused, nothing sent), never "stopped" by default; a stand's own fallback is named where one exists (switching PFS off stops a PFS-driven Z move); a `FakeCore` whose `stop()` raises reproduces the case; a safety argument that rests on stopping a move in flight states which stands it holds for.
- **FM-118 An autofocus that moves to its own reference, not to the operator's focus.** Engaging the Ti2-E's PFS drives Z to the plane its stored offset names: with an offset left from earlier use, Z went +235 µm between two 100 ms reads, past the Z soft limit, while `isContinuousFocusLocked()` already read True and `deviceBusy("ZDrive")` read False (#208, #205). The soft limits guard commanded moves only, and a poll cannot catch a move that ends between two reads. *Check*: an engage reads Z before it switches on and at every poll until it has settled, and Z past a soft limit or a bound switches the autofocus off and raises an error that names both positions (an error, not a refusal: something moved, FM-64), and says that a poll limits a jump without preventing it; nothing treats `locked` as "settled" or `busy` as "PFS is moving Z"; on a stand that declares the behaviour, the offset an engage relies on is one the layer has read locked with this objective since the stand was opened, or the engage is refused with nothing sent (m2 §12).
- **FM-119 A device position quantised below what the caller asks.** The Ti2-E's `PFSOffset` holds whole units: 7927.5 reads 7927 and 7925.75 lands on 7925, so a contract that moved by 0.5 and 1.25 with a 0.5 tolerance failed although the guard behaved (#208, #207). *Check*: a test or a guard that compares a commanded position with its read-back allows for the device's step (or uses whole steps), and a `FakeCore` device that truncates reproduces it (`FakeCore.hold_whole_units`; the contracts' `fake` stand holds whole units).
- **FM-127 A benign outcome that masks a fault.** Of several calls that can each raise (a stop and the stops linked to it), one error is raised and the others only logged. Once one of them became "not a fault" (a refusal the profile declares, FM-117), `return error or failure` raised the harmless `StopRefusedError` of Z's own stop and dropped the failure of the PFS switch-off linked to it: the caller was told nothing is broken while PFS, still on, could drive Z (adversarial review of #204; reproduced at the `Executor` and on a Ti2-E fake). *Check*: wherever several outcomes collapse into one, a fault wins over an outcome that says nothing is broken, whatever their order; a test makes the benign one and the fault happen together and expects the fault.
- **FM-129 A recovery that cannot tell a lost state from the operator's choice.** The scan engaged the autofocus again whenever a field read `is_locked()` False, so a PFS the operator switched off in the middle of a scan was switched back on at the next field, which on the Ti2-E drives Z to the plane of the stored offset (FM-118), the very thing the plugin promised never to do (adversarial review of #213, reproduced on the demo with a fake autofocus). "Not locked" covers a lost lock (on, searching), the loop's own failed recovery (the protocol switches it off) and an operator's switch-off, and only the first two are the loop's to undo. *Check*: a loop that restores a device state reads why it is not in that state, and restores only what it lost or switched off itself (it keeps a flag for its own); a test switches the device off from outside mid-loop and finds no restore call, and the mutant that drops the reason is killed.
- **FM-133 A busy check that ends a wait early is also the check after the give-up.** The engage guard's `Motion.is_busy` returned idle on a Z read that failed or left its bound, to end the lock wait at once. The `Executor` calls the same `is_busy` after a give-up's stop, to decide whether the motion stays registered: at the deadline, with the switch-off failed and Z unreadable, the first poll after the stop read idle, so the registration was dropped while PFS stayed on and the error said "it may still move Z" (adversarial review of #205, reproduced on the Ti2-E fake). *Check*: a busy check that can say "idle" for any reason other than "the device stopped" knows when the wait is over (its deadline, taken no later than the `Executor`'s), and from then on reads only whether the device can still move; a test fails the stop and the reason together, after the deadline, and expects the motion registered. Not a flag set by the motion's stop: the `Executor` also resends that stop after the command when a stop came during it, and the wait goes on.
- **FM-134 A sliding window that a late poll empties.** The settle window dropped the reads older than `settle_s` before it added the new one: a poll late by more than `settle_s` (a stall, a slow read) left the new read alone, a spread of 0, and "settled" after a 5 µm move (adversarial review of #205, reproduced with a fake clock). *Check*: a window that must span a time keeps the newest read from before it, so a new value is always compared with one from before the gap; a test with a fake clock makes one poll late and moves the value during the gap.
- **FM-98 An exception kept where its own traceback reaches it.** A frame that keeps a caught exception in a local, or that raises an exception it holds, is on that exception's traceback: exception, traceback, frame, local, exception is a cycle on every Python version, and it keeps every object of those frames, the core included, until the cyclic collector (FM-92's consequence: the abort of #142 at the exit of a command). *Where it hides*: a returned `error` (`_send_safe`'s), an exception raised by a function that took it as a parameter (`_refuse_if_cancelled`) or from a closure cell (`do()`'s `cancelled`), a `failure` or `interrupted` collected over a loop (`_stop_linked`, `_stop_stages`), and the arguments of a log line held until later (`hold_log`'s `lines`, when an argument is the error itself: `_send_safe` passes `repr(error)` since #166); the error a caller keeps after `_send_safe` returned it (`_give_up`, and `_stop_linked`'s device stop error: the error's traceback reaches the caller's frame through `_send_safe`'s `f_back`); a closure's list of caught exceptions, which its owner must empty on **every** exit, the normal return included (`_engage`'s `switch_off_failures`: a Z stop's safe call ends the lock wait through `switch_off`, then the call returns); and an exception handed between two threads through a shared object (`_ZStop.switch_off_failure`, whose traceback holds the stopping thread's frames, which hold that object): the reader sets `closed` and then clears it, and the writer, after it has set `finished`, clears it if `closed` is set, so whichever finishes last clears it, with plain stores (FM-70) (#163). *On 3.11+*: a `@contextmanager` that raises a different exception from the one thrown into it makes the same cycle through contextlib's frame (the generator's `f_back`, whose local `value` is the original exception), and no `del` inside the generator breaks it. *On 3.10*: a class that calls a `@contextmanager`'s `__exit__` by hand with a live exception (`_EndedByAZStop._end` leaving `linked_stop`) gets that exception back with contextlib's frames added to its traceback, and contextlib's frame holds it (3.11+ restores the traceback, and a `with` statement does too): save `exc.__traceback__` before the call and restore it in a `finally`; measured on 3.10.10, all the Z-stop freeing tests failed without it (#163). Measured on `main` 5592a7d (macOS, py3.13, `gc.disable()`): through the real `smc.cli.main()`, `stage jog 100000 0` (exit 2), `z jog 1e6` (exit 2) and a 60 s demo timeout (exit 1) left the facade and the core alive, `stage get` (exit 0) freed both, and with `_reported` a class all three error exits freed them; the generator leaks on 3.13 and not on 3.10, the same conversion in a class leaks on neither, an exception held in a local and raised through its frame leaks on both, and `try: raise error` / `finally: del error` leaks on neither (#148). *Check*: a frame on the path clears what holds the exception before it ends (`try: raise error` / `finally: del error`; a held list cleared once written; a closure's exception in a list its owner empties, since ruff reads a `del` of the closure's variable as undefined); a context manager that converts an exception is a class, which keeps none on `self`. Never drop `__traceback__`: `--debug` and the log need it. `smc.cli.main()` collects after the command, and an exception that escapes `app()` (`--debug`) is not covered. `test_error_exits_free_the_core.py` runs each error path under `gc.disable()`, and a new error path of a stop, a safe call or a CLI exit goes in there. *Test hazards*: `FakeCore.failing` keeps the instance it raised, whose traceback holds the fake's frames, so clear it before the drop (or raise a fresh error each time); patch a fake's method as an instance attribute and `del` it, never `monkeypatch.setattr` on the core (it keeps the original bound method, and so the core) and never restore it by assigning the bound method back (a self-cycle); `CliRunner` adds a cycle of its own through `SystemExit`, so drive `cli.app(args, prog_name="smc")` inside `try/except SystemExit`; pytest keeps every `LogRecord`, and a failed stop's record holds the error, so the freeing tests disable logging; a test thread helper that keeps what its target raised (`_Thread.error` in `test_mm_autofocus.py`) is a cycle (the error's traceback, `_run`'s frame, `self`), so reduce the error to its text or type name and clear it before the drop (#163).

## Windows

- **FM-20 Redirected output is cp1252 with strict errors.** `✓` crashes `smc doctor > f.txt` (#42). - **FM-21 Text files without `encoding=`** are decoded as cp1252. *Check*: ruff `PLW1514`.
- **FM-22 A child sharing the console can change its code page** (`[Console]::OutputEncoding` in PowerShell). *Check*: `creationflags=CREATE_NO_WINDOW`.
- **FM-23 A child's stdout uses the ANSI code page.** *Check*: ASCII-only protocols, or explicit encodings on both sides.
- **FM-24 Paths.** Spaces, backslashes, platformdirs' layout (`%LOCALAPPDATA%\pymmcore-plus\pymmcore-plus\…`), files that cannot be replaced while open. *Check*: `pathlib`, no string surgery, no assumptions about the layout. A path compared with a literal compares *flavours*: `WindowsPath("a/b") != PurePosixPath("a/b")`, so a test that passed on macOS and Linux failed on both Windows jobs (review of #122); compare `as_posix()`. A tool that groups work by path keys one file twice when the file system folds case and `Path` does not (macOS's default volume) or when two names are one inode (a hard link): the second edit overwrote the first, and a mutant with one edit instead of two read as SURVIVED (adversarial review of #177). Compare files with `samefile`, not with `==`. A read is refused as a rename is (antivirus, a sync client or a backup agent holds a file that was replaced a moment ago): the run document's read, which begins every `write_stage` and so every checkpoint, retries on `PermissionError` like its `os.replace` (adversarial review of #18; a stand-in refuses `Path.read_bytes` four times, then allows it; not run on Windows). A path that a plugin stores to be moved with the run folder is stored as `Path.as_posix()`, relative to it: a Windows `str(Path)` has backslashes that another OS does not read as separators.
- **FM-101 A test that takes a committed text file's bytes as its fixture.** The repository has no `.gitattributes`, so a Windows checkout with Git's default `core.autocrlf=true` gives a committed `.cfg` CRLF line endings. A test that copies the file's raw bytes and then looks for `b"...\n"` in what the code wrote fails there, although the code keeps the file's own CRLF correctly: two capture tests of #14 passed on macOS and failed on a CRLF copy (adversarial review of #14). A fixture read from a file the code itself edits (`profiles/nikon-ti2.cfg`, which a capture at the stand rewrites) also moves with every commit of that edit. *Check*: normalise the bytes the test copies (`replace(b"\r\n", b"\n")`) before choosing the line ending under test, or compare with the file's own ending; keep the expected data a literal, with one test that compares the literal with the committed file; run the test once on a CRLF copy. A fixture that the test writes itself is CRLF on Windows too when it goes through `Path.write_text` (newline translation): two tests of #177 with an LF pattern passed on macOS and Linux and would have failed there. Write it with `newline="\n"` or `write_bytes`.
- **FM-25 PowerShell 5.1.** `ConvertTo-Json` prints an object, not a list, for one item. No BOM with `[Text.Encoding]::UTF8` on a pipe (checked on a Windows runner, 2026-09-23).
- **FM-26 An undeclared `ctypes` Win32 return type.** A `ctypes.windll`/`WinDLL` function called without setting `.argtypes`/`.restype` gets ctypes' default `restype` of `c_int` (32-bit); a `HANDLE` or other pointer-sized return value can be silently truncated on 64-bit Windows (adversarial review of #64). *Check*: every Win32 function reached through `ctypes.windll` declares `.argtypes` and `.restype` from `ctypes.wintypes` before the first call.
- **FM-27 A C `long` is 32-bit on Windows.** An MMCore parameter declared `long` (`setTimeoutMs`) takes values up to 2**63 - 1 on Linux and macOS, where CI runs, and only up to 2**31 - 1 on Windows, where the SWIG binding raises `OverflowError` (adversarial review of #8: a `device_timeout_ms` above about 24.8 days). *Check*: a value that reaches a `long` parameter is bounded at 2**31 - 1 where it enters (the profile validator), so every platform rejects it with the key's name.
- **FM-75 A float cast to an unsigned integer.** `np.rint(x).astype(np.uint16)` of a negative or NaN float wraps or is undefined in C, so it differs by platform: a dark pixel read 65 516 where it should read 0 (a dark background with noise, or a negative blob; the lower bound of the clip had no test), and a blob radius below about 1e-154 made `radius**2` underflow to 0, so a pixel on its centre got 0 / 0 = NaN, cast to garbage (adversarial review of #10). *Check*: clip to the type's range before the cast and refuse non-finite inputs and ranges whose square or ratio underflows (a lower bound on a radius or a width); a test with an all-dark frame plus noise and one with a negative-intensity feature asserts that the maximum is small, not wrapped.
- **FM-80 A profile that is not UTF-8, or has a byte-order mark.** Notepad saves cp1252 or UTF-16 when asked for "ANSI" or "Unicode", and before Windows 10 1903 its "UTF-8" starts the file with a mark. Reading with `encoding="utf-8"` (FM-21) raises `UnicodeDecodeError` past the loader, which the CLI printed as `✗ unexpected UnicodeDecodeError` without the file's name; a mark makes `tomllib` report `Invalid statement` at a line that is fine (measured 2026-10-13, #93). *Check*: the loader reads bytes, decodes `utf-8-sig`, and turns a failure into a `ProfileError` that names the file and the line and says to save it as UTF-8; the test writes the file as cp1252, as UTF-16 and with a mark, and loads it through the CLI too.
- **FM-112 Registration written at install time, read after a `git pull`.** Entry points (and console scripts) live in metadata that pip writes when the package is installed. A microscope PC updated the documented way (`git pull`, no reinstall) does not see a plugin that the pull added: `smc run --list` printed "no plugin is registered", and `smc run stage-report` "no plugin named 'stage-report' (available: none)", neither saying to reinstall, and the setup document's update step did not either (adversarial review of #18; reproduced against the main venv's older metadata, which is OS-independent). *Check*: a message that finds no plugin at all says to run `pip install -e .` in the smc folder; the update step of `docs/hardware/microscope-pc-setup.md` reinstalls after the pull; tests assert both messages. Any new registration through metadata is checked against the update procedure of a PC, not only of a worktree (`worktree.py setup`).
- **FM-83 One long wait that Ctrl-C cannot end (Windows).** `Popen.wait(timeout=...)` is a single blocking `WaitForSingleObject` there, which a Ctrl-C does not interrupt, and a child created with `CREATE_NO_WINDOW` does not receive it either: the terminal looks frozen until the child ends or the timeout passes, 300 s in `mutant.py` (review of #122, from the source of `subprocess.py`; not run on Windows). *Check*: wait in slices of about 0.5 s against a deadline, so that Python runs its signal handler between two of them; the same holds for a timed `Event.wait` or `Lock.acquire` (#158: the wait for a Z stop's outcome polls in `time.sleep` slices); a test records the `timeout` of every `wait` on a `Popen` subclass and finds none above 1 s, and another raises `KeyboardInterrupt` from the first `wait` and finds the child dead (FM-35).

- **FM-116 A `ValueError` contract that `Path.resolve` breaks.** On Windows `ntpath.realpath` re-raises a `winerror` outside its tolerated list (64, a network name that was deleted, is not in it), so `Path.resolve()` on a run folder on a share that drops raised a bare `OSError` out of `resolve_in_run`, past `load_cells`'s `except ValueError`, and the reader's "run cells again" never ran; the same drop was diagnosed one line later by the read (adversarial review of #199, from the source of `ntpath.py`; not run on Windows). *Check*: a function that promises a `ValueError` that names its input wraps every call that touches the file system, `resolve` and `is_file` included, in `except OSError` and chains it; a test patches `Path.resolve` to raise `OSError` and finds the `ValueError`. A caller that reads that `ValueError` as "not there" turns a dropped share into a missing file: the scan's resume told the operator to drop a night's checkpoint (adversarial review of #213), so a caller looks at its `__cause__` and reports an `OSError` as a folder it cannot read now.

## Processes, CLI and files

- **FM-30 Artefacts after the console.** A broken pipe or Ctrl-C while printing loses files written afterwards. *Check*: check the destination before long work, write files first, one-line errors.
- **FM-31 External calls without a timeout.** *Check*: every OS tool and child has one, and its failure becomes a note ("failures are findings").
- **FM-32 Unbounded options.** `nan`, `inf`, negative or huge values reach `subprocess`. *Check*: bounds plus `math.isfinite`.
- **FM-74 A bound that the work goes around.** A limit on the argument is no limit on the allocation when the code then grows the input: a blur padded a frame by 4 sigma on each side, so a one-row frame at the pixel bound became 4.3e9 values, 34 GB. Nor is it one when the check multiplies the caller's own integers: two `np.int32` of 60000 wrap to a negative product below the bound (numpy < 2 on Windows makes `np.array([...])` int32), and the product of two small dtypes warns, which `-W error` turns into a failure (adversarial review of #10). *Check*: the bound is applied to the size of what is allocated, after padding, in Python ints (`int(h) * int(w)`); tests give a one-row frame at the bound with the largest padding, the largest legal frame with the largest padding (still allowed), and a shape of numpy integers; the refusal comes before any allocation (a test that would allocate gigabytes is not run before its guard exists: stop at a stub, or test the check alone). A size derived from a float goes around it too: `3200.0 // 5e-324` is `inf`, `int(inf)` is an `OverflowError`, and `candidate_step_fraction=1e-9` is a legal parameter (planning #194), so the number of lattice points of `route` is bounded **on the float**, before `int()`, written `not x <= bound` so that `nan` is refused as well, and the product of the two axes is bounded in Python ints after it. *Check* (this too): a test with a step of 5e-324, 1e-300 and `nan`, each a refusal that is not an `OverflowError`, and the largest legal lattice still allowed.
- **FM-77 A path expanded from input raises outside the error taxonomy.** `Path.expanduser()` raises a bare `RuntimeError` for `~nosuchuser` (POSIX) or when no home directory can be found. Left alone, it ends `smc profiles` at the first such file with "unexpected error", and a caller that catches `HardwareError` misses it (#77; `config` had the same gap). *Check*: wrap it where a profile or a caller's path is resolved, and re-raise as `ProfileError` or `CoreError` naming the key and the entry; the test patches `Path.expanduser`, because Windows has no `~user` failure to provoke.
- **FM-78 An empty string is the working directory.** `Path("")` is `.`, so an empty entry in a list of directories (a profile key, or `os.environ.get("X", "")` for an unset variable) silently makes the current folder the first place that DLLs and adapters are taken from (#77). *Check*: refuse empty and whitespace-only entries where the list is validated *and* where it is consumed: a profile can be built or changed in code after validation, and a library caller never passes through it.
- **FM-81 A value that contains the separator of the list it is joined into or split from.** `PATH` is written and `$SMC_PROFILES` read with `os.pathsep`, and a folder name may contain it (`;` on Windows, `:` on POSIX). A value written as it is reads back as two entries, and every later write adds both again: `PATH` grew by two entries on every open of a profile whose adapter folder was named `mm:odd` (measured 2026-10-13, #110). A list that is only read (`$SMC_PROFILES`) reads such a folder as two directories, with no growth and no guard. *Check*: refuse or skip such a value where the list is written and say so (a WARNING that names it); test twice in a row that the list does not grow, building the value with `os.pathsep`, never a literal `:` or `;`, and skipping the test, with the reason, where the file system refuses the folder. Another writer can have written the pieces first (pymmcore-plus's override does, before `open_core` runs, and they stay): also try an ordinary entry equal to the first piece (`a` beside `a:b` still grew `PATH` by one entry per open, a known limit of #110, see design §7 and #119).
- **FM-113 Third-party code read outside the findings taxonomy.** The plugin registry checked that a plugin's members existed, not what they held: a `summary` of `None`, or a property that raises, passed `discover()` and then ended `smc run --list` for every plugin with `unexpected TypeError` (and before Python 3.12 even `isinstance(instance, Plugin)` calls such a property, through `hasattr`) (adversarial review of #18). A package on a microscope PC is code nobody here reviewed. *Check*: every member that a command reads is type-checked at load, and the whole inspection, the `isinstance` included, sits inside one guard that turns an exception into a finding (`LoadFailure`) while `KeyboardInterrupt` and `SystemExit` pass; tests give a plugin with a `None` summary and one whose property raises, find the others still listed, and the mutant that lets the exception out is killed.
- **FM-128 A validator that raises something other than `ValueError`.** Pydantic turns a validator's `ValueError` (and `AssertionError`) into a `ValidationError`, which the profile loader names by file and key; anything else escapes. `stop_refused_by`'s validator looked an entry up in a set before checking it was a string, so a doubled bracket (`[["xy_stage"]]`) or an inline table raised `TypeError: unhashable type` out of `Profile.load`, and every command on that profile printed `✗ unexpected TypeError … file an issue`, no key named (adversarial review of #204). *Check*: a `mode="before"` validator checks the type of each entry before it hashes, compares or indexes it; a test feeds a nested array and an inline table through `Profile.load` and finds the `ProfileError` naming the key.
- **FM-82 A crash with the exit code of a verdict.** A tool whose exit code means something (`mutant.py`: 0 killed, 1 survived) ends with 1 when an exception goes uncaught, so a crash reads as a verdict: with the "file is in an ignored place" check removed, a `FileNotFoundError` in the copy exited 1, "the test cannot see that line" (adversarial review of #122). The same trap sits in what the tool runs: `python -m pytest` exits 1 when pytest is not installed, and 0 when every test was skipped. *Check*: `main` maps any unexpected exception to the "no verdict" code, with the traceback on stderr, after the clean-up has run; a verdict needs evidence that the run did what it claims (a baseline that passes, at least one test passed); a test makes a step raise `OSError` and finds the no-verdict code and no verdict line.
- **FM-33 A child's working directory is on `sys.path`.** *Check*: children run from a neutral directory.
- **FM-34 A failed write hides the report.** Writing the files first (FM-30) and exiting on an `OSError` loses the on-screen result of minutes of work (review of #47). *Check*: on a write error, still print what was collected, then the one-line error and the exit code.
- **FM-35 Killed is not gone.** `kill()` stops only the direct child: a helper process it started survives and may keep holding the hardware, and a process stuck in a driver call may not die, so an unbounded `wait()` after `kill()` hangs (review of #47, reproduced on macOS). *Check*: the wait after `kill()` has a timeout and its failure is a note; kill the process tree where helpers are expected. A tree kill that itself fails (`taskkill` denied or missing) but leaves the direct child dead is not a clean stop: the note says so — "could not be stopped" — instead of reading as resolved with the failure buried as a trailing detail (two reviewers, #50).
- **FM-36 Rich markup eats bracketed text.** `console.print` parses `[...]` as markup and silently drops what it cannot style: `[roles.assign]` vanishes from a `CapabilityMissingError`, `[core]` from a `RoleMap.describe()` line, `[dry-run]` from a result line, and `[safety]` from a Typer help text under `rich_markup_mode="rich"` (measured with rich 15, 2026-09-30, plan of #11). *Check*: text the CLI did not write as markup (an exception message, a device label, a role line) is printed with `markup=False` or as a `rich.text.Text`; help texts contain no `[...]`; a test asserts that a bracketed phrase reaches the output.
- **FM-37 Rich wraps at the console width, and that width depends on who runs it.** When stdout is not a terminal, rich wraps at 80 columns, so a one-line error becomes two lines in a redirected log. Rich measures the terminal on file descriptors 0-2, not on the captured stream, so a `CliRunner` test that matches a phrase passes in a wide local terminal and fails in CI (measured, rich 15, 2026-09-30). *Check*: error and result lines are printed with `soft_wrap=True`; CLI tests pin the width (`CliRunner(env={"COLUMNS": "200"})`, which rich reads on every print).
- **FM-72 Typer forces colour on GitHub Actions, and rich styles an option name in pieces.** When `GITHUB_ACTIONS` is set, typer renders `--help` as a terminal would although stdout is captured, so ANSI codes surround the text and split `--force` into `-` and `-force`. A `CliRunner` test that looks for a flag in help output passes locally and fails on every CI platform; and a flag that the command's docstring also mentions satisfies a word search without the option being declared (measured on the five CI jobs of #84, reproduced locally with `GITHUB_ACTIONS=1`; the reviewer's `--forced` rename shows the substring trap too). *Check*: a help test compares plain text (strip `\x1b[...m`) and finds one row carrying the whole flag (`--force\s`, since `--forced` contains `--force`) and its own help text; run the CLI tests once with `GITHUB_ACTIONS=1` before pushing.
- **FM-38 A file overwritten in place.** A writer that opens its target with `"wb"` (tifffile does) truncates it before the first byte, so a Ctrl-C or an error half-way through leaves a broken file where an earlier good result was, and the one-line error does not mention it (adversarial review of #11). *Check*: write to a temporary file in the same folder and `os.replace` it onto the target, with one `try` around both: a Ctrl-C between two separate blocks leaves a temporary file that nothing names. Remove it on any failure but one: when only the rename failed (Windows refuses to replace a file another program holds open), it holds the whole result, so it is kept and the error names it. Create it with the mode a plain write gives (`os.open(..., O_CREAT | O_EXCL, 0o666)`): `mkstemp`'s 0600 survives the rename and leaves every result readable by its owner only (review of #89). A test interrupts the write and finds the earlier file intact and no partial file left; another fails the rename and finds the new file kept and named.
- **FM-39 A verdict from one read, a report from another.** A check that reads the hardware to decide its exit code, then reads it again to print its report, can disagree with itself when a device answers one read and not the other (a flaky serial line): `smc doctor` printed `XY ?` beside its ✓ and exited 0 (adversarial review of #89's fix round). *Check*: read once, and build the verdict and the printed report from that one snapshot; a test makes a stub fail on its first call only, then on its second only, and finds the line and the exit code agreeing both times.
- **FM-107 A generated file that drops what it does not generate.** `nikon-control`'s rebuild of a Micro-Manager configuration deleted every line outside eight directives, typed state labels included, and carried presets that named devices the new file no longer loaded: a preset applied half of itself, or failed when it was selected (read for #15, 2026-10-20). A file a human also edits is the generator's input as much as its output. *Check*: every line the generator does not write comes back, carried whole or set aside as a comment that the next run reads again (`# not carried: <line>`); a block that names a device the new file lacks is set aside whole, never in part; and the invariant is a test over generated previous files, not a list of cases (`test_a_line_the_build_does_not_write_always_comes_back`). "Lines it writes itself" means those it wrote *this time*: a `Device` line of an adapter the build did not walk (a serial port's, an Arduino's) comes back too, and the first version dropped it. And the parser is total: a line of only commas, which a spreadsheet's blank row is, is blank and not an `IndexError` (adversarial review of #15).
- **FM-108 A safety copy that blocks the result.** `smc config build --force` saved the previous file as `.bak` before writing the new one, and when the `.bak` step failed (Windows antivirus holding the file, FM-24) the new configuration, minutes of hardware work, was written nowhere, while the error said "the new file is kept as" a file that held the old bytes. A step that precedes the write can fail, and must not take the result with it (adversarial review of #15). *Check*: when a preliminary step fails, the result still reaches the disk, beside the target, and the message names the file that holds it; a helper that keeps its temporary file on failure (`_replace`) is not used for a copy whose temporary file holds something else.
- **FM-109 A hint that blames the last thing the child said.** The advice `re-run with --skip <device>` came from the last progress line on the child's stderr, so a child stopped by the deadline blamed whichever device was slow, a vendor DLL printing `reading C:/vendor/x.ini` named `vendor/x.ini`, and a non-ASCII device name written in the console's code page named no device at all (adversarial review of #15). *Check*: the line must name an adapter the build was given; a stop by the deadline offers the longer timeout too; the child writes its progress in UTF-8, the encoding the parent reads.

- **FM-115 A cleanup that removes a name the operation did not create.** `write_atomically` removed its temporary file on any failure, including the `FileExistsError` with which `O_EXCL` refused a name that was already there: the file it deleted was someone else's, and the write it had refused was reported as if it had cleaned up after itself (adversarial review of #199; the odds are 2^-32 per write, the rule is free). *Check*: remove only what the operation made (`os.open` returned), and let `O_EXCL`'s refusal leave the name alone; a test pre-creates the temporary name, fixes `secrets.token_hex`, and finds the file untouched and the error chained to `FileExistsError`.

XY and Z do (measured for #11), but the White Light Shutter reads open on some opens and closed on others (measured 2026-10-01, #89's fix round), so the test fails at random. *Check*: compare what is measured to be fixed at open, or patch the read so that both sides see one snapshot.

A stand that starts 30 µm from its X limit then takes a 60 µm forced jog the profile would have refused (adversarial review of #9). *Check*: the harness's limits must lie inside the profile's own; when they do not, the test fails before anything moves and says to move the stand towards the middle of its travel.

At a stand, the operator then believes Z is back when only the XY restore was reported (adversarial review of #9). *Check*: every step is attempted, and one error names each step that failed, chained to the first; a test makes two steps fail and finds both named. The cleanup catches it too, still runs the steps that stop the stand and cut the light, and names the rest as not attempted; a test raises it from a step. Then see FM-71.

A pytester run whose first test's cleanup gets a Ctrl-C ends `INTERRUPTED`, never runs the second test, and still closes the stand.
- **FM-73 Symmetric test data hides swapped axes.** A test whose data is square, isotropic, or probed along one axis passes with width and height, the x and y pitch, or a circle and a square exchanged. Every blob and blur test of the synthetic sample used a square frame, and the geometry test probed only along a plate's column axis on plates whose x and y sizes are equal: a circle turned into a square, a transposed blur crop and a y pitch read from x each left all 93 tests green (adversarial review of #10). *Check*: for every code path that treats two axes differently, one test uses a non-square frame or an anisotropic plate and probes off the axes (a diagonal), and the mutant that exchanges the two is killed. A cheap oracle: a non-square render equals the middle of a larger square one rendered at the same pose.
- **FM-84 A test that passes because the harness already did it.** The code under test sets an environment variable, and the test runs where it is already set, here by an outer run of the same script when its own mutants are checked: the mutant that removes the line survives (review of #122: `PYTHONDONTWRITEBYTECODE`). The same holds for a variable the CI sets (`COV_CORE_*`, `GITHUB_ACTIONS`). *Check*: the test removes the variable first (`monkeypatch.delenv`) and asserts the effect; the mutant that drops the line is killed.
- **FM-85 A position read while the demo stage still travels.** The demo XY stage simulates its travel: `setXYPosition` returns at once, and a read right after it gives a fraction of the move (`(0.2, 0.4)` for a move to `(10, 20)`, measured in #120). A test that reads right after a raw core move asserts on a stage in motion, and a real stand behaves the same. *Check*: wait for the stage (`waitForSystem()`, or the facade's move, which waits) before a position is read; never assert on a read that follows a raw `setXYPosition` directly.
- **FM-86 A liveness-after-kill test that reads too early.** A test that proves a killed process is gone by comparing two reads, the first taken right after the kill returned, fails when the signal is delivered a tick late: `killpg(SIGKILL)` only queues the signal, and on a loaded runner the grandchild wrote one more heartbeat (`8 == 7`, macOS CI, #131). The code was right; the test raced it (FM-35, FM-44). *Check*: wait until the output has been quiet over a window of 1 s (several periods of the writer) against a deadline of about 10 s, and fail only at the deadline; never `os.kill(pid, 0)` as the probe (it kills the process on Windows and answers "alive" for a POSIX zombie); bound the helper's own lifetime so that a failing run does not leak it; show once that the test fails on the mutant that kills the direct child only.
- **FM-96 A threading test that pins an order the fake's speed decides.** A test asserts a whole log and an error that hold only because the `FakeCore`'s stops take microseconds: `close()` during a relock switched PFS off, stopped the stages, then stopped Z, and the test expected the Z stop to reach the relock's link. Stress the test with a tiny switch interval.
- **FM-94 An assertion inside a callback the layer swallows.** A test hook that runs inside a stop, a busy check or a close (to hold a give-up open while a second thread acts) is called through code that catches `Exception` by design (`_send_safe`, `_keep_while_moving`). - **FM-102 A test that pins what a stdlib parser refuses.** `argparse` reads a value that starts with a dash after an option with `nargs=3` as another option on Python 3.10, 3.11 and 3.13.0 (exit 2, "expected 3 arguments") and takes it on later 3.13 and on 3.14: a test of the refusal passed on three CI jobs and failed on three (#177). - **FM-110 A load-back test that the loader's defaults answer for.** MMCore picks the only camera, XY stage, autofocus and shutter of a configuration by itself, so a test that loads the built file and reads `getCameraDevice()` passes with the `Property,Core,Camera` line removed; the AutoFocus slot was pinned by nothing until a mutant said so (adversarial review of #15). *Check*: read the generated text for the line, or give the stand two devices of the type so the default cannot stand in; and run a mutant of the line, as `/develop` step 10 says.
- **FM-123 A transitive merge joins distinct objects.** De-duplication by connected components (single linkage, union-find) chains two distinct objects through a third view: one box of frame 1 between two cells of frame 0 left one cell for two, and two neighbours seen twice with a 0.8 µm calibration error between the fields lost one of the two (measured, planning #23, m3 §9.0). The merge looks right on a cell seen twice and is wrong only where cells are dense, which a test of one cell seen by two fields never reaches. *Check*: each kept view removes at most one view from each other source, the nearest, and a grid hash only finds the candidates; a test puts a box between two cells of another frame and finds two cells, and a test of two neighbours seen by two fields finds two. ## Concurrency (the layer's own locks and threads)

Learned from the design review of #59, where `/code-review` reproduced 15
races in the first motion guard.

- **FM-60 A motion found by name.** A waiter or a stop looks up "the" motion of a device by its label, and finds another caller's or none. A stop is lost, a stopped move reports an arrival, a stale waiter stops a new move. *Check*: only the action that sent a command waits for it, holding the lock; a stop is a per-device generation the action compares, not a flag on whatever registration exists (design §13).
- **FM-61 A give-up by a bystander.** A thread that only waits for someone else's motion stops it when its own short deadline passes. *Check*: only the thread that started a motion stops it when giving up.
- **FM-62 Log before stop.** A stop path that writes its log line first is delayed by a blocked console (a QuickEdit selection on Windows), or skipped by a second Ctrl-C. A step between the stop and its log line (a busy check, a registry update) that is interrupted skips the line too, so the log never shows a stop that was sent (adversarial review of #59's third round). A path that sends several stops in a row and logs each one as it goes holds the next stop behind the previous line: the emergency stop did, Z behind XY (#76). *Check*: send the stop, then log, and write the line in a `finally` around whatever runs in between; several stops in a row are all sent before the first of their lines; an interrupt in one of several stops in a row is held until the later ones are sent, then re-raised (`Executor._stop_linked`, `MMAutofocus._on_z_stop`, #166).
- **FM-63 A readback in its own lock section.** Another caller acts between the end of the wait and the readback, so the move returns another move's position and a set returns another thread's value. *Check*: command, wait and readback in one lock section.
- **FM-64 A halt that can be caught as a refusal.** `except SafetyRefusedError: skip` swallows the emergency stop, and the loop carries on. *Check*: the halt error derives from no error that a tool is expected to catch and carry on after, and a halt since the call is checked before every other refusal on every path an action takes: the lock wait, re-entry and the section itself (#80).
- **FM-65 An interrupt between `acquire()` and `try`.** A Python-level lock wrapper (a generator context manager) leaves a window in which a Ctrl-C keeps the lock held for good; `with lock:` has none. *Check*: nothing between `acquire()` returning and the `try`; a test interrupts the main thread (`_thread.interrupt_main()`) while it waits for the lock.
- **FM-66 A check that is not the last one.** A halt (or any flag set without the lock) checked before a slow step, such as the guard polling a serial device, lets the action run after the flag was set. Bookkeeping added between the last check and the command reopens the window: recording what the action waits for did (adversarial review of #68). *Check*: check the flag again immediately before the command, after any bookkeeping.
- **FM-67 One caller's outcome kept under a shared key.** A record of how a caller's operation ended (a stopped `wait=False` move) is keyed by the device alone, so another caller's new operation on that device erases or replaces it, and the first caller's later `wait()` reports on the other move and misses its own stop (adversarial review of #59's fix round). *Check*: key per-caller state by caller and resource; a test has a second thread act on the same device before the first one asks how its operation ended.
- **FM-68 A give-up before the command.** The path that stops a motion when its action fails also runs for an interrupt that lands before the command was sent. It stops a stage that nobody commanded, or logs that a turret "cannot be stopped from smc" (adversarial review of #68). *Check*: an action gives up only from the point where its command may have reached the device; a test interrupts it just before the command and sees no stop and no give-up line.
- **FM-69 A teardown from inside the action it tears down.** `close()` called on the thread that is inside an action (a Ctrl-C handler that runs during a move's wait, a callback inside a snap) re-enters the `RLock` and unloads the devices; the action then touches a device that no longer exists and raises a bare `RuntimeError` from MMCore instead of a `HardwareError` (adversarial review of #8). *Check*: a teardown that finds the lock already held by its own thread stops what moves, releases nothing and raises, so the caller closes again once the action has returned; a test calls it from inside a stub's busy poll.
- **FM-89 A sequence of actions whose steps record their own call.** A compound (suspend the autofocus, move Z, engage it again) runs several actions in one lock section. Each nested action recorded its stop generation when it was itself called, after the compound had waited for the lock and run the steps before it. A `ZStage.stop()` pressed while the Z move queued, or during the suspend, was therefore lost and the move was sent; a `disengage()` during the move was undone by the relock, so PFS ended on after a switch-off that reported success (adversarial review of #13). *Check*: the sequence records the stop generations and the halt mark when it is called, before it waits for the lock, and every nested action compares with those; a test stops the device while the sequence waits for the lock, and between two of its steps, and finds nothing sent after the stop; another sends the safe call during the main step and finds no restore.
- **FM-91 A stop that misses a motion moving its axis or the stand.** Stops are keyed by device: a stop reaches the actions keyed by its device's label, and the emergency stop reaches the devices on its list. A motion keyed otherwise is missed. PFS locking again, or following its offset, drives Z under keys of its own (`PFS`, `PFSOffset`), so a `ZStage.stop()` during the relock was ignored and PFS searched on for up to `lock_timeout_s`. The offset device, a role with no capability, was not on the emergency stop's list, although `moving()` reported its move, which then held the lock until its timeout (review of #140). A motion about to start counts too: a Z stop that landed while a locked `focus_by_um` read its offset's anchor switched PFS off but let the offset move go out after it, because the link stopped the offset device only once `moving()` named it (adversarial review of #140's fix round). *Check*: for every motion the layer can wait for or register, name the stops that must end it: its own, the stop of the axis it drives, the emergency stop and `close()`. Such a stop also cancels the motion's command when it is not sent yet. A test runs each motion in another thread, sends each such stop, and finds the motion's stop in the fake's log, its action raising `MotionStoppedError`, and nothing left in `moving()`; another sends the stop just before the command and finds no command in the log.
- **FM-97 A linked stop's outcome read before it has run.** `Executor.stop` marks a link as reached when it takes its snapshot, before it calls the linked stop. The action whose block ends meanwhile reads "a stop reached me, and nothing failed", and reports PFS "left off" while the switch-off is still on its way. When that switch-off then fails, PFS is on and the tool was told otherwise; the "may still move Z" WARNING is never written. Measured with a switch-off that takes 0.4 s and then fails: "left off" at 159 ms, the failure at 565 ms, PFS on at the end (adversarial review of #144; the window dates from #140, and #144 makes it reachable from `engage()` and the offset moves). *Check*: an action that reads the outcome of a stop another thread runs waits, bounded, for that stop to finish before it reports; a test makes the linked stop slow and failing and finds no "left off" claim. The wait is bounded (`Z_STOP_OUTCOME_WAIT_S`, since the waiter holds the microscope lock), and a stop that has not returned by then is reported as a failure ("may still move Z"), never as done (#158). It waits for the one step whose outcome it reports (the switch-off), not for the whole linked stop: a slow offset stop after a switch-off that worked was reported as "could not be switched off". A halt or an interrupt does not wait, and goes on at once with what is known (adversarial review of #158): one that ends the action, and one that comes during the wait (the halt is read from the stand's halted state, the exception that ended the block being the Z stop's own `MotionStoppedError`); an interrupt in the wait logs what is known, as one that ended the action (#166).
- **FM-70 A plain lock on a path a signal handler re-enters.** Python runs a signal handler on the main thread between two bytecodes, so a Ctrl-C handler that calls `stop()` or `close()` can run while that same thread holds any lock the stop path takes. A `threading.Lock` then blocks for ever and sends no stop: the facade's capability cache did, when the handler landed inside `has()` (design review of #8). `Executor._registry_lock`, which `halt()` takes, was one too; #76 makes it an `RLock`. Re-entry has its own trap: the handler runs at any point of the section it interrupted, even inside one statement, so a section that iterates the registry, or checks an entry and then deletes it, finds it changed. *Check*: every lock the stop and close paths take is an `RLock`, or they take none, and a lock hidden in a primitive counts (`threading.Event.set()` takes a plain `Lock`: a flag the stop path sets is a plain store, adversarial review of #158); every section under such a lock stays correct if a stop runs at any point inside it (iterate a snapshot taken in one call); a test runs the stop from inside the locked section, in a thread with a join timeout (FM-44).
- **FM-93 A holder that still waits for a motion it gave up on.** While the give-up sends the stop, checks busy and writes its line, the holder still records "waiting for" the motion, so a queued action is refused or run depending on how long those take; a slow log handler made a queued move fail (#101). *Check*: once a give-up has registered its motion, the holder stops recording "waiting for" it before any device call or log line; a test has a contender poll the lock during the give-up (FM-44: an event, not a sleep).

## A server and a view (the plate page)

Learned while planning and building the plate page (#197), on Panel 1.9.4 and 1.10.0.

- **FM-143 A server that swallows the operator's Ctrl-C.** A blocking `panel.serve` returns normally on Ctrl-C (Bokeh installs its own SIGINT handler): no `KeyboardInterrupt` reaches the caller, the command exits 0, and nothing says that the operator interrupted, so a run going on and the stand's release are handled as for a server that simply ended (measured, POSIX; Windows not measured). *Check*: the server runs in a thread (`threaded=True`) and the main thread waits in slices of 0.1 s (also what lets Ctrl-C through on Windows, FM-83), where the `KeyboardInterrupt` is the command's own; the first one stops the server, a second one during the wait for a run is the CLI wrapper's (exit 130, FM-71); a test raises the interrupt from a stand-in thread (FM-44), never a signal.
- **FM-144 A port taken that no one is told of.** With `threaded=True` the server's thread dies with an `OSError` traceback on stderr after `serve` has returned, so a taken port looks like a server that started (measured). *Check*: the command binds the port once and closes it before it opens the stand (`port N is in use; choose another with --port`, exit 2, a spy proves the stand was not opened), and `serve` raises when its thread ends without Ctrl-C (`the plate page's server stopped on its own (is port N taken?)`, exit 1); a test gives a thread that is not alive.
- **FM-145 A refresh that rebuilds an O(wells) structure on every tick.** `well_geometry` for every well takes 1.7 ms for 96 wells, 22 ms for 384 and **339 ms for 1536**: a status poll that rebuilt the plate would spend the 1536-well time four times a second (measured). *Check*: the wells are built once per `(plate, a1_center_xy_um, rotation_deg)` and kept; the periodic callback reads only `status()`, and the view is rebuilt on an event (a click, a typed range, a capture, the end of a run); a test counts the `well_geometry` calls across two views and a click, and another the `view()` calls across ten ticks.
- **FM-146 A view's lifetime taken for the work's.** A page that stops its run when its tab closes ends an overnight scan because a laptop was shut; one whose run belongs to a session that is gone leaves nothing to stop it. *Check*: the controller belongs to the server and a session's widgets and callbacks to the tab; only STOP, the end of the server (`close()`, which stops a run and waits for it) and the plugin's own end stop a run; a test builds and drops a second view while a run goes.
- **FM-147 A widget spelling that warns on the version the lab installs.** Panel 1.9.4 and 1.10.0 raise `PendingDeprecationWarning` for a widget's `name=` and for `Button(button_type=...)`; a warning on a version that CI resolves later fails every test that runs with warnings as errors, and fills the console of a PC that has it (measured). *Check*: the page spells `label=` and `color="danger"`; its tests run with `PendingDeprecationWarning` as an error, and a new warning is fixed at the call, never filtered.
- **FM-148 A server's console log on the loop that handles STOP.** Bokeh logs through its own console handler at the level of the root logger, and opening a core leaves the root at DEBUG (pymmcore-plus, measured): the page printed a route table at its start and chatter through a session, on the loop that also handles the click on STOP. A console that blocks (a QuickEdit selection on Windows, FM-62) then blocks that loop. *Check*: `serve` sets the `bokeh` logger to WARNING while it serves and puts the level back, and passes `verbose=False` (the command prints its own line); a test reads the level at the call of `pn.serve` and after it, on the Ctrl-C path and on the path of a server that ended alone; the smoke on the demo shows one line.
- **FM-149 A server stopped before the work it carries.** On Ctrl-C the page stopped the Bokeh server first and the run second: Panel's `StoppableThread.stop` ends with a join that has no limit, and the server's shutdown waits for the callback in flight and then 5 s, so a tick blocked in a slow device read held the stop of a scan back for as long as the read (measured: 12 s for a 6 s tick, 24 s for a 12 s one, with `join(timeout=10)` after it never applying). The same ordering mistake with a non-daemon server thread started outside the `try` that stops it leaves the process alive after the stand is released (#197 review). *Check*: the stop of the work is sent first (`close()`: the run's event, then `Microscope.stop()`), then the server; the server's stop is asked from a daemon thread and waited for in slices against a deadline, and said when it does not end; everything after the server's start is inside the `try`/`finally` that stops it; a test makes the server's `stop` block on an Event and finds the run's stop already recorded and `serve` back within the deadline, and another raises from the console write.
- **FM-150 A port probe on one address family.** Tornado resolves `localhost` with `AF_UNSPEC` and binds every address (`::1` and `127.0.0.1`), so an IPv4-only probe passes a port that is held on `[::1]`, the stand is opened, and the server then dies (reproduced on macOS; Windows resolves `::1` first). *Check*: probe every address of `getaddrinfo("localhost", port, SOCK_STREAM, AI_PASSIVE)`, skipping an address this host cannot bind (`EAFNOSUPPORT`, `EADDRNOTAVAIL`); a test holds the port on each loopback address in turn (skipping a host without IPv6) and another makes IPv6 unavailable.
- **FM-151 A view that does not draw what the shared controller holds.** The selection, the plate and the captures belong to the server's controller while each tab draws its own copy, and a tick that never redraws leaves a second tab showing no selected wells while its Run sends `wells=A1,A2` (measured, #197 review). *Check*: a tick compares the few attributes the map draws (never rebuilds the view when they are the same) and redraws when another tab changed one; a test taps in one view and ticks another, and one counts `view()` calls across ticks with and without a change.
- **FM-152 A test's HTTP client that takes the PC's proxy.** `urllib.request.urlopen('http://localhost:...')` honours `http_proxy` and, on Windows, the Internet Options of the registry: a lab PC with a proxy that does not bypass `localhost` fails the test after its retry loop, on a page that is fine (measured, #197 review). *Check*: a test that talks to its own server uses `build_opener(ProxyHandler({}))`.
