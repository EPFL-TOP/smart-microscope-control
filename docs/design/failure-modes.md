# Failure modes the code must survive

The project's shared checklist. `/plan` names the entries an issue must
handle; the adversarial reviewers (`.claude/agents/`) go through the ones
that apply to a change. Every entry was learned on this project or its
predecessors. **Add an entry** whenever a review confirms a failure whose
category is not here: an id, what happens, and how to check.

## Vendor DLLs and Micro-Manager adapters

- **FM-01 Prints while loading.** An adapter writes to stdout or stderr, with or without a newline. Any protocol over stdout breaks. *Check*: results travel through a file or a dedicated channel, never "the last line of stdout".
- **FM-02 Crashes or hangs while loading, or at unload.** A result already produced is lost when the parent trusts the exit code. *Check*: adapter work runs in a child; the child writes its result before teardown and calls `os._exit(0)` after the final write; the parent reads the result whatever the exit code.
- **FM-03 A crash dialog (Windows, macOS).** On Windows, a missing dependency or the crash reporter opens a modal dialog, which looks like a hang. On macOS, a crashing `Python.app` (Homebrew) makes ReportCrash show "Python quit unexpectedly" once per crash, `pytest` runs included (#47). *Check*: processes that load adapters guard themselves first: `SetErrorMode(SEM_FAILCRITICALERRORS | SEM_NOGPFAULTERRORBOX)` on Windows, and on macOS libc `_exit` as the raw handler of the crash signals (`_mm_child._no_error_dialogs`). A reproduction that crashes a native process on macOS goes through the same guard, or says in its evidence that it will open a dialog.
- **FM-04 Helper processes inherit the pipes.** The pipe never reaches end-of-file; on Windows `subprocess.run(timeout=…)` then waits without limit after `kill()`. *Check*: child output goes to files; `Popen.wait(timeout)` then `kill()`.
- **FM-05 Non-UTF-8 strings.** pymmcore decodes with `surrogateescape`; one lone surrogate makes the JSON invalid. *Check*: strings from adapters are sanitised before they are serialised. A file written as UTF-8 is a sink too: a `.cfg` saved in cp1252 gives an objective label with a lone surrogate for its `µ`, the run document (ASCII JSON) keeps it, and the report's `page.encode("utf-8")` raised a bare `UnicodeEncodeError` that is no `PluginRunError` and names nothing (adversarial review of #195, reproduced). The page is encoded with `errors="replace"` and the stage says so in a WARNING, so the file is written and the damaged text shows as `?`; `test_a_lone_surrogate_in_a_record_is_written_as_a_question_mark_and_warned`.
- **FM-06 Listing devices contacts the hardware.** `NikonTi2` asks the Nikon SDK, and a stand accepts one connection at a time (NIS-Elements, ZEN, a second core). *Check*: the default test suite never lists vendor adapters; surveys run with the vendor software closed.
- **FM-07 Hub-based adapters.** Peripherals appear only after the hub initialises (`getInstalledDevices`). *Check*: probe and configuration code asks the initialised hub.
- **FM-08 Pre-init properties.** Serial devices need `Port` before `initializeDevice`; failing without it is not a hardware fault. *Check*: detect it and report "needs a port".
- **FM-09 One message, many causes.** "Failed to load device adapter" hides missing DLL, wrong SDK, wrong bitness and interface mismatch. *Check*: ask the OS (`ctypes.WinDLL`, WinError code) when the diagnosis matters, in a child process (FM-95).
- **FM-95 A loader probe in a process that already holds the DLL.** Windows resolves a module that the process has already loaded by its base name, so a second `ctypes.WinDLL` probe in the same process can pass while the adapter's own dependency is missing: `nikon-control` probes the vendor DLL first and then the adapter in one process, so the second answer cannot be trusted (from the loader's documented behaviour; not reproduced). The same process also holds the vendor DLL for good, and a `DllMain` that crashes or hangs takes the caller with it (FM-02). *Check*: one child process per probed DLL, started as the adapter children are (FM-04, FM-22, FM-33, FM-35, FM-83), and the parent never loads a vendor DLL; a probe with no verdict (a hang, a crash, no such file, not Windows) is "not probed", never "will not load"; a test replaces the child's command by a canned script, since no test may load a real DLL (FM-40).
- **FM-105 A clean row for what was not tested.** A probe reported `ok` for a hub whose 14 peripherals it never loaded (`SequenceTester`: one device listed, 14 reported after the hub initialises; the Ti2-E: `Ti2-E__0 ok`, no peripherals, `Notes (0)`, #126), read an empty device list as a clean one, and gave a serial device that has no `Port` yet a verdict of its own: `ok` or a hardware fault, when nobody had set the port (#48). *Check*: every row says what was tried; what was not tried is `not-probed` with a `reason`, never `ok` and never `failed`, and the report prints three words (`ok`, `FAILED`, `not probed`); a device the adapter lists and its hub does not report, and one whose pre-init `Port` is empty or `Undefined` and was not given one, have no `loadDevice` or `initializeDevice` in the core's call log; an empty list or a hub that reports nothing is an `error` that carries the stand's meaning; `ProbedDevice.ok` is a property, so no serialised `ok` key can read as a pass.
- **FM-106 A partial result that reads as a whole.** A result file written once, at the end, loses a long probe to a crash (the Ti-E's `TIDiaLamp` has crashed Micro-Manager, so seventeen good rows would go with it); one rewritten after every device reads as complete if nothing marks it, and a reader takes the rows it finds for the whole adapter (#48). *Check*: the walk calls a checkpoint with a deep copy, `complete=False`, once before the first device and after every row, and only the value it returns is `complete=True`; the child's checkpoint writes the file and survives an `OSError` (Windows antivirus, FM-24) as a line on stderr, never as the end of the probe, and swallows nothing else; the parent keeps the partial probe whatever the exit code; the report's title says `INCOMPLETE` for `complete=False`; the crash test finds `probe` not `None` and not complete. The last checkpoint holds the rows, not the `error`, the notes and the `complete` that come after the last one, so the child writes the whole result *before* it releases the probe's core (an unload can hang or crash, FM-02: written after it, a probe that had finished read INCOMPLETE and lost its error, adversarial review of #48), and `_write` waits and retries `os.replace` on `PermissionError`, since the final write is the one nothing else repeats (FM-24); a test records what the result file holds at the moment the core is released, and another holds the replace twice.

## Micro-Manager core

- **FM-10 Timeout shorter than the move.** MMCore's 5 s default is shorter than a plate traverse. *Check*: `setTimeoutMs` from the profile (60 s).
- **FM-11 Device-interface mismatch.** An MMStudio install and pymmcore-plus with different device-interface versions: a `.cfg` from one fails silently in the other. *Check*: report both versions.
- **FM-76 An extra search directory replaces what it holds.** MMCore takes each adapter from the first search directory that has its file, and does not fall back to the next one when that file fails to load. A profile's `adapter_search_paths` (the MMStudio folder) therefore supplies *every* adapter it holds, so one device-interface mismatch (FM-11) fails the whole stand, not only the adapter that was missing (#77). *Check*: a failed load names the directories in the order they were searched, and the setup doc says so; a test stands in for the failing load. A remedy that the tool prints after such a check names the folder of the adapter MMCore takes, not the install's: `smc install-driver ti2` without `--to` copied the driver beside an adapter the profile did not load, exited 0, and left `doctor` saying the same thing; the advice now carries `--to "<that folder>"`, and a test puts the profile's folder before the install's (adversarial review of #12).
- **FM-79 A device fault outside the error taxonomy.** MMCore reports a device fault (a serial timeout on a read, a camera timeout on a snap, an unplugged cable) as a bare `RuntimeError`. Left alone, it reaches the CLI as `✗ unexpected RuntimeError … file an issue`, so the operator files a bug instead of checking the device, and a tool that catches `HardwareError` misses it (#93, found in the review of #89). The translation has its own trap: `HardwareError` *is* a `RuntimeError`, so a handler that catches `RuntimeError` without letting `HardwareError` pass first wraps a `SafetyRefusedError`, or the emergency stop's `MicroscopeHaltedError` raised by a callback inside a command, into a fault. *Check*: one place in the backend turns a core call's `RuntimeError` into a `HardwareError` that names the role and the call, chained `from exc`; every `HardwareError` and every non-`RuntimeError` passes untouched; a test makes the core raise (`FakeCore.failing`, or a patched method of the demo core; patching a capability's own method bypasses the layer and proves nothing), and another raises a `SafetyRefusedError` from inside a core call and finds it unchanged.
- **FM-12 Moving Z switches PFS off** on the Nikon stands. On the Ti2-E a nosepiece turn does too, by the stand itself, and the stand moves Z during the turn (Ti2-E session 2, #330). *Check*: suspend and re-engage around Z moves, and re-engage only after a move that completed (FM-88, design m2 §3.4).
- **FM-13 Several devices share a type.** Ti2: four `XYStage` devices, three of them TIRF positioners; Ti-E: three `Stage` devices. *Check*: type-first resolution with exclusions, and the candidates reported.
- **FM-87 A call that acts on a core slot, not on a label.** MMCore's continuous-focus calls (`enableContinuousFocus`, `isContinuousFocusLocked`, `setAutoFocusOffset`, `fullFocus`) and its camera calls take no label: they act on the device that the core's slot names. A role resolved to another device (a profile's `[roles.assign]`, a configuration without `Core,AutoFocus`) then switches or reads the slot's device while the layer reports the role's. With the slot empty, `enableContinuousFocus(True)` raises `Auto-focus focus device not defined.` (measured on the demo, 2026-10-16, plan of #13). *Check*: the facade points the slot at the role once, and every slot call first checks that the slot still names the role's label and refuses otherwise, as `MMCamera` does; a test assigns the role to a second device and finds the slot moved, then changes the slot behind the layer and finds the call refused.
- **FM-92 A reference cycle keeps the core alive until the cyclic collector.** A capability that holds the facade (or another capability that holds it) strongly, that stores a bound method of itself (`SafeCall(send=self._send_off)`), or whose call leaves an object and its callback pointing at each other (`_ZStop.link` and the lambda that `linked_stop` registers, made by every Z move with PFS on), makes a cycle through the core: dropping the facade frees nothing, and the `CMMCorePlus` is destroyed by the cyclic collector at a moment nobody chose, at the exit of a command during interpreter finalization. Up to Python 3.13 a thread still inside MMCore (its 21 pool threads, measured) then takes the process down: `smc doctor`'s child aborted with `FATAL: exception not rethrown` on `ubuntu-latest, py3.10` and timed out on `macos-latest, py3.13` after #140 (#142; the abort itself was not reproduced, the cause was). *Check*: capabilities reach their siblings through a weak reference to the facade, and refuse with a `HardwareError` once it is gone, never with `None`, which reads as "no such device" (FM-12); nothing a capability stores is a bound method of that capability; an object that a call creates and a callback it registers do not refer to each other once the call has returned; `test_a_dropped_facade_frees_its_core_without_the_cyclic_collector` builds every capability, runs each thing the stand does once (a Z move with PFS on, a locked `focus_by_um`, a direct `engage()`, `set_offset_native` and `offset_by_native` with PFS on) under `gc.disable()`, and finds the facade and the core dead; a new capability or a new compound goes into `_use_the_stand`. A cycle that only a call makes passed the test that only built (#142's review). The operator's Z stop path frees too (#163): after a Z stop inside any autofocus compound (the relock, a locked `focus_by_um`, a direct `engage()`, `set_offset_native` or `offset_by_native`, a stop once it has locked again, a stop before the relock's block, a stop that reached a block which ended meanwhile), with a switch-off that succeeds, fails, or fails after the compound stopped waiting for it, or with Z's own stop failing, on Python 3.10 to 3.13, the facade and the core are freed by reference count; `test_a_z_stopped_autofocus_compound_frees_its_core_without_the_cyclic_collector` and its neighbours in `test_mm_autofocus.py` pin it, and the closing edges were FM-98's. One cycle is left, by decision: a lock wait given up whose switch-off failed stays registered, so the stand refuses until `resume()`, and its `Motion` (`stop`, `is_busy`) holds the autofocus, which holds the `Executor`. The facade is freed; the core only once `stop()` and `resume()` succeed or the cyclic collector runs, and `smc.cli.main()` collects after every command (#148). The stand is already in a fault state that asks the operator to act, and breaking the cycle would take weak callbacks in `Motion`, a change to the registry's contract (`lock-wait-given-up` in `test_error_exits_free_the_core.py`). A log call never passes an exception as an argument, only its text (`exc_info=True` counts; `%r` of an exception becomes `%s` of `repr(exc)`, #166; the text is then built by the caller, where `logging` used to swallow a failing `__repr__`, so a path that must not raise guards it: `_send_safe`'s `_repr_of`, `_named`): a kept record (caplog, a GUI log pane) keeps the traceback and the core through it (#158). A test that drops a core and finds it alive: look first for a `LogRecord` kept by pytest whose arguments hold it (pymmcore-plus logs `Initialized core %s` at DEBUG), then for a cycle (`gc.DEBUG_SAVEALL`).
- **FM-179 A vendor core freed on its own notification thread.** MMCore delivers its callbacks asynchronously, on a thread of its own (`NotificationQueue` in the SWIG module): `setExposure(15)` returns and `exposureChanged` arrives 0.1 ms later on a `Dummy-N` thread, and the XY and Z position changes come from there too, so pymmcore-plus's relay runs Python on that thread and a garbage collection can start there. A core freed while it is still delivering one of its own notifications aborts the process: `CMMCorePlus.__del__` calls `registerCallback(None)` (its error suppressed), then the C++ destructor calls it again and throws `CMMError: Cannot call registerCallback from within an MMEventCallback handler` out of a destructor (`libc++abi: terminating`, `Fatal Python error: Aborted`, the thread "Garbage-collecting", no Python traceback on the main thread). A core in a reference cycle (FM-92) is freed by the cyclic collector on whichever thread runs it, and `unloadAllDevices` queues notifications of its own, so one is often in flight right after a close. Measured on macOS, py3.13, pymmcore-plus 0.18.1: 1 run in 40 of `tests/contracts` and three demo test files aborted, inside `tests/contracts/test_autofocus.py`, and both macOS CI aborts happened during `tests/test_cells_demo.py`; neither depends on the live view or the UI, since no smc code subscribes to `core.events` (#311). *Check*: every path that releases a core detaches its relay from the releasing thread **after** unloading: `close_core` and `Microscope.close()` end with `detach_callbacks`, which calls `pymmcore.CMMCore.registerCallback(core, None)` (through the base class: `CMMCorePlus.registerCallback` is overridden to refuse) and so blocks until the handler in flight has returned; it releases the GIL while it waits, so a handler that collects does not deadlock it. The wait has no limit of its own, and a `close()` from inside a callback of the same core is a WARNING and not an exception. Not a test fixture that collects, which would hide the defect and leave the UI service (Connect and Disconnect, #303) exposed. A test frees a core while its handler still runs, in a child process (the abort takes the interpreter down), and asserts that the child survives: `test_a_core_freed_while_it_delivers_a_notification_does_not_abort_the_process`, on both paths, exit -6 before the guard and 0 after on macOS; it asserts `== 0` and never a failure code (the code of an abort differs by platform, and under the crash guard), goes through the discovery probes' crash guard before it loads anything (FM-03: a regression ends in `abort()`, which opens a crash dialog that looks like a hang), reads the child's stderr with `errors="replace"` (a Windows child writes cp1252, FM-42) and opens `Profile.demo()` only (FM-40). The detach is in a `finally` after the unload: a second Ctrl-C inside it is a `KeyboardInterrupt`, not an `Exception`, and a step queued after it would be skipped (FM-49); `test_a_failing_unload_does_not_skip_the_detach_in_close_core` and `..._in_microscope_close` make the unload raise an error and a `KeyboardInterrupt` on both paths, and the mutants that drop the `finally` or detach only after a good unload are killed. A wrapper that delegates to a core (the doctor tests' `_FailingCore`) is not an MMCore, so `close_core(wrapper)` cannot detach the core it wraps: its owner releases the wrapped core through `close_core`. The wait is one native call that a Ctrl-C does not end (two interrupts sent during it took effect after 5.0 s, when the handler returned); a Ctrl-C that unwinds a `with Microscope.open()` block or `opened()` gains it, the signal handler's `stop()` does not.
- **FM-99 An API that merges where the caller meant to replace.** MMCore's `defineConfig` changes or adds one setting of a preset and keeps the others, and it accepts the label of a device that is not loaded without a word (measured on the demo, 2026-10-19, m2 §8.1). A capture that redefines a preset of the same name therefore keeps every stale setting the new one does not name: `nikon-control`'s did, and the next `setConfig` then fails on the ghost device or applies the old one (plan of #14). *Check*: delete before defining, and validate what the API does not (the device is loaded, the value fits the file it goes into); a test defines the preset with an extra setting first and finds it gone after the capture, and the mutant that drops the delete is killed. The replacement is then whole, so it says what it dropped: recapturing the lab's `BF` loses its shutter states and its exposure, and a WARNING names each setting dropped and added (adversarial review of #14). A read over every preset skips one that names a device that is not loaded, rather than failing on it (FM-19).
- **FM-100 A match by string on a value the device reformats.** MMCore stores a number it is given in its own format: a preset's `Camera,Exposure,10`, once applied, reads `10.0000`, and `getCurrentConfig`, which compares strings, then names no preset at all (measured on the demo, 2026-10-19). The Ti2-E's `BF` sets `Exposure` 10 and `Intensity` 210, so MMCore would report no current channel right after selecting it (m2 §8.1); confirmed on the stand, where every value matched after `setConfig("Channel", "BF")` and `getCurrentConfig` read `""` (Ti2-E session 2, #334). *Check*: compare numbers as numbers (equal strings, or two finite floats that are equal; `nan` never matches), never with `getCurrentConfig`; a test applies a preset written `10`, finds the device reading `10.0000`, and finds the preset current; the mutant that compares strings is killed.
- **FM-104 A vendor core's derived value that passes an invalid input through.** MMCore's `getPixelSizeUm()` divides its pixel-size preset by the magnification factor and passes an invalid factor on: a factor of 0 reads infinity, -1.5 reads -0.667, NaN reads NaN (measured on the demo's optovar, 2026-10-20). Infinity is above 0, so a check of `value > 0` alone reported it as a measured pixel size (#167). *Check*: `math.isfinite` on every number the core returns before it is used or compared, both the derived value and the input the layer divides or multiplies by; a test with 0, a negative number, NaN and infinity for each, asserting the whole warning (FM-45); the mutant that drops the finiteness check is killed.
- **FM-14 Turret moves can crash an objective** under a loaded plate. *Check*: turret moves require confirmation.
- **FM-15 A blocking device call under the microscope lock.** A vendor call with no timeout of its own (`snapImage`, a driver deadlock) holds the one `Executor` lock, so every other capability on that stand hangs with no diagnosis (#5 review). *Check*: waits poll `deviceBusy` against a deadline; callers of a lock held too long fail with `MicroscopeBusyError`, which names the holder (design §13); a call with no timeout of its own says so in its docstring.
- **FM-16 A wait that holds the lock.** Polling a moving device while holding the microscope lock blocks every reader and every stop for the length of the move, which is 60 s for a plate traverse (#54). *Check*: reads and the safe calls (stop, closing a shutter) never take the lock, and another caller's action is refused at once while the holder waits for a motion (design §13, revised after #59); a test reads, stops and closes the shutter from another thread while a move waits.
- **FM-17 A wait that gives up leaves the device moving.** A timeout, a Ctrl-C or any other exception during the wait raises, but the stage keeps going while the caller believes the move failed (#52 review). *Check*: every exit from a wait other than "idle" sends the device's stop first; so does a command that raises.
- **FM-18 A stop that races a command.** A stop that does not wait for the lock can reach the device just before a move command already under way, which then starts the stage after the stop (#54). *Check*: a stop that arrives while a command is being sent is sent again after it, and the move raises `MotionStoppedError`.
- **FM-19 A busy state that cannot be read.** `deviceBusy` raises. Reading that as idle lets the next action run during a move; reading it as moving forever locks the stand. *Check*: unreadable counts as moving, the refusal names the error, and a stop or `resume()` releases it; a motion that cannot be stopped (a `State` device) must still have a way out (#59 review). The same holds for any state read before acting: a read that only decides whether to add a safeguard (linking the Z stop to an offset move) counts unknown as the state that adds it, with a WARNING that says so; a read that decides what moves (Z or the offset in `focus_by_um`) refuses (#158).
- **FM-88 A restore step that moves after a failure.** A sequence that puts something back after its main step (re-engaging an autofocus after a Z move, returning to a start position) is itself a motion. Run from a `finally`, it moves the stand after the operator's stop, a halt, a timeout or a fault: re-engaging PFS drives Z (design m2 §3.4, plan of #13). *Check*: the restore runs only when the main step returned normally; on any exception it is skipped, a WARNING says what was left as it is, and the exception propagates; a test stops, halts and faults the main step in turn and finds no restore call in the fake's log.
- **FM-90 A move through another device skips the guards of the axis it moves.** `focus_by_um` with PFS locked changes focus through the PFS offset, and PFS then drives Z by the same distance; the offset's own guards are in its own units and optional, so the Z soft limits, which no Z move may pass even forced, did not apply: a 30 µm change at Z 99 went through where `move_by_um(30)` was refused at a limit of 100 (adversarial review of #13). The fix sat in `focus_by_um` only, and a locked `offset_by_native(30.0)` still drove Z 30 µm past the limit (review of #140). *Check*: every call that moves an axis indirectly, the low-level ones included, checks that axis's guards on the estimated target before it sends anything, not forceable where the direct move's are not; where the conversion is unknown, its docstring says that only the indirect device's own guards apply; a test sets the axis's limit just past the start and finds each indirect call refused with an empty log. When an unforceable guard and a forceable one would both refuse **at the same point** (both before the lock, or both on the same reading inside the action), the unforceable one runs first: named second, it would meet a `force=True` that the first refusal invited (#158). A guard that needs no reading (a jog) still runs before anything is read, so that a refused jog takes no lock and reads nothing; a target refused after it (a relative target, read inside the action) names itself, and cannot be forced either (#166).
- **FM-117 A stop the device refuses.** On the Ti2-E, `core.stop()` raises `Unsupported device command (11)` for `XYStage`, `ZDrive` and `PFSOffset`, idle or moving, and a move that was sent runs to its target: a Ctrl-C during a 20000 µm jog was logged as "stop failed", then printed as "any move under way was stopped", and the stage went all the way (Ti2-E session 1, #208; #204, #206). FM-17's "send the stop first" protects nothing there. *Check*: every message after a stop says what the stop's outcome was (accepted, refused, nothing sent), never "stopped" by default; a stand's own fallback is named where one exists (switching PFS off stops a PFS-driven Z move); a `FakeCore` whose `stop()` raises reproduces the case; a safety argument that rests on stopping a move in flight states which stands it holds for. A line that sums up an interrupt (the Ctrl-C line) is built from what the layer knows, the notes the stops left plus what the registry still tracks when the stand is released, never from the absence of a note: a Ctrl-C inside `wait()` on a stage that an earlier refused give-up left tracked left no note, and the line said "no move was under way" while it travelled (#224, E6; `Microscope.__exit__` notes it, for a `KeyboardInterrupt` only, and a stage whose drive never reads busy, the Ti2-E's Z, still cannot be known). A stop that raised on a role the profile does not declare is `failed`, not `refused`, since the layer never parses the device's text, and every outcome has its own clause with a test that goes through every member, so that a member added later cannot fall into another one's words (#224, E4).
- **FM-118 An autofocus that moves to its own reference, not to the operator's focus.** Engaging the Ti2-E's PFS drives Z to the plane its stored offset names: with an offset left from earlier use, Z went +235 µm between two 100 ms reads, past the Z soft limit, while `isContinuousFocusLocked()` already read True and `deviceBusy("ZDrive")` read False (#208, #205). The soft limits guard commanded moves only, and a poll cannot catch a move that ends between two reads. *Check*: an engage reads Z before it switches on and at every poll until it has settled, and Z past a soft limit or a bound switches the autofocus off and raises an error that names both positions (an error, not a refusal: something moved, FM-64), and says that a poll limits a jump without preventing it; nothing treats `locked` as "settled" or `busy` as "PFS is moving Z"; on a stand that declares the behaviour, the offset an engage relies on is one the layer has read locked with this objective since the stand was opened, or the engage is refused with nothing sent (m2 §12). The refusal's advice is never the route that jumps: D1's first text sent the operator to the stand's PFS button, which drove Z +206.6 µm, 48 µm past the soft limit, at an unseen offset on a new plate (Ti2-E session 2, #331). The way out it names is a first lock from below: the offset set to its floor with the autofocus off, then an engage whose band bounds Z toward the sample only; and on such a stand an offset move with the autofocus on needs a lock and a factor (m2 §12.10).
- **FM-119 A device position quantised below what the caller asks.** The Ti2-E's `PFSOffset` holds whole units: 7927.5 reads 7927 and 7925.75 lands on 7925, so a contract that moved by 0.5 and 1.25 with a 0.5 tolerance failed although the guard behaved (#208, #207). *Check*: a test or a guard that compares a commanded position with its read-back allows for the device's step (or uses whole steps), and a `FakeCore` device that truncates reproduces it (`FakeCore.hold_whole_units`; the contracts' `fake` stand holds whole units).
- **FM-188 A read right after a set returns the previous value.** The Ti2-E's `DiaLamp` read `210` 9 ms after a set of `501`, and the new value 0.3 s after a set (Ti2-E session 2, #334). A layer that returns the read-back as what was applied then reports the old value (`MMLightSource.set_intensity_native` did until #330), and one that compares it with what it sent reports a failure that did not happen (`drive.switch_light` would print `light on, although off was sent` if `State` lags too; not measured) (#330). *Check*: a read-back that stands for what the device now holds re-reads until the value is fresh or a bound passes, or says that it may predate the set; a `FakeCore` property that reads its previous value for a while after a set reproduces the case (`FakeCore.make_reads_stale`). Since #330 the three read-backs that stand for what a device holds go through `_reread` within `FRESH_READ_WINDOW_S` (read at the call): the lamp's intensity, `Channels.select`'s match and the turret's label (a shutter's state and `Properties.set` do not: not measured to lag). Fresh after a wait is an INFO line (a read that was repeated is a wait of at least one poll interval, whatever the clock measured: FM-197), the bound a WARNING, and the return is the last read, never the first. Tests: `test_a_stale_read_is_read_again_until_fresh` (the helper), `test_a_stale_read_after_a_set_is_read_again_and_the_new_value_returned` (the lamp), `test_a_select_whose_lamp_reads_stale_for_a_while_still_returns_bf` and `test_the_turns_label_is_read_again_until_it_is_the_label_asked_for`; the mutants that make `_reread` believe its first read, swap the INFO and the WARNING branches, or read the window at import (`test_the_window_is_read_at_the_call`) are killed. The operator turned back to the 10× and ran `--resume`: the checkpoint is complete, its objective is the 10×'s, nothing is visited, the end read finds the 10×, and the plate is fitted on 208 points, 108 of them in the 40×'s frame, `done`, with nothing in `assumed` (adversarial review of #340). *Check*: a refusal that says "do not resume" leaves nothing a resume can use: the checkpoint is reset to what is still true (the centre and the objective, no point) before the refusal is raised, and a test turns back and resumes and finds the survey made again from the first point; the mutant that keeps the points is killed.
- **FM-142 A measurement placed where it was commanded, not where it was taken.** `plate-finding` built each survey point from the target it sent and dropped the readback that `move_to_um` returns. A stage that stops short of a target without an error (clamped at 45 mm in the test) gave a survey of the 12-well plate whose fit was `done`, scored 0.6 and had A1 26 mm (a pitch) off, with `assumed` empty; placed where the stage said it was, the survey spans 90 mm and the extent check refuses it (adversarial review of #20). *Check*: the position a frame or a point is recorded at is the device's readback after the move, never the command; a readback that is not finite is a failed point; a stage wrapper that clamps and reports where it is makes the test, and the mutant that records the command is killed.
- **FM-164 An abort rule in proportion to the total is a time budget of total/10 times the timeout.** `plate-finding` ended a survey when more than a tenth of its points had failed. A stage that fails every move then costs a tenth of the survey before anything says so: 21 moves of 208 on a 12-well survey (measured), 113 of 1120 on a 96-well survey, which is 1.9 h at the 60 s move timeout of the shipped profiles (computed, plan of #248). *Check*: a loop that skips failed units and ends on a proportion of failures also bounds the failures **in a row** (`max_failed_in_row`, `scan`'s name), checked first, restarting at 0 on a resume, and the budget `total/10 x timeout` is worked out when the bound is chosen; a test makes every move fail and counts the moves (3, not 21), another has two in a row twice amid successes (a sampled point resets the count), another makes the bound a parameter, and one mixes the kinds of failure (a raised move, a frame that is `nan`, a readback that is `nan`); the mutants that drop the rule, check it after the tenth, never reset it, carry it over a resume or count only one kind are killed.
- **FM-165 A label that dies with the attempt that earned it.** `plate-finding` added `the autofocus was switched off for the survey` to `assumed` at the switch-off, a branch taken only when the autofocus was engaged at the start of that attempt. A survey stopped and resumed found the autofocus already off, skipped the branch and ended `done` with `assumed == ()`: the scan, which never switches the autofocus on, then ran without a lock and nothing had said so (measured: stop at the 120th snap, resume, #248). *Check*: a statement about the state the next step will find is **read from the device at the end of the work**, after every check that can refuse the result, and neither set where the loop changed it nor kept in the checkpoint (a flag there is silent when the operator switched the device off and stale when the operator switched it on again); the read is in a `try` of its own: a halt or a motion stop passes (FM-64), any other failure becomes a line of its own (FM-155), built outside the handler (FM-98); a test stops and resumes and asserts the line, another has the device change state before the end, one makes the read fail, one makes it raise a halt, and a refused fit reads nothing; the mutants that build the line from a flag, read before the fit's checks or drop the halt's pass-through are killed.
- **FM-166 A `done` with no product.** `scan` ended `done` with 12 failed fields and no frame whenever `max_failed_in_row` was above the number of failures (measured on the demo with `max_failed_in_row=100`, plan of #228). The stage downstream, `cells`, refuses a scan with no frame, and a `--resume` of the `done` stage is refused too (`scan finished`), so the operator found out hours later, at the next stage. *Check*: a stage applies its consumer's first refusal itself, after the last unit of work and before it is `done`: no product from this attempt and none from a checkpoint is a failure, and the message says how to start again (a resume skips what it already walked); a test fails every unit of work below the in-a-row bound and finds the error, the checkpoint kept, and the same refusal from a resume with no new move; another keeps one frame among the failures `done`, one resumes with a checkpoint's frames (`done`), and a dry run, whose walked moves are its units, is held to the rule; the mutants that ignore this attempt's successes, the checkpoint's frames or the dry run are killed.
- **FM-167 A command whose readback is recorded and never compared with it.** `scan` stored the readback of every move in the frame (`x_um`, `y_um`) and compared it with nothing, so a move that returned without an error and landed 6 µm off wrote a frame of the wrong place, which the cells stage then maps from (measured on the demo with a stage wrapper that adds 6.0 µm to one move, plan of #228; FM-142 is the same readback used as the position). A move that returns is not a move that arrived. *Check*: the readback is compared with the target as a distance over both axes, within a tolerance taken from the geometry (a fraction of the smaller side of the field of view, FM-73), and written so that a number that is not one fails it (`not error <= tolerance`, FM-104); a field that did not arrive is failed before anything else is read or moved for it (no autofocus call, no snap, which would drive Z for nothing), and a dry run, whose readback is the target, is not compared; a test lands a field short on each axis of a non-square frame (5.5 µm against 4.8 where the larger side would take it), 3.5 µm on both axes (4.95 against 4.8), 4.0 and the tolerance itself, and a `nan` readback; the mutants that use the larger side, one axis, `<` for `<=` or `>` for `not <=` are killed. The tolerance is a parameter, because the first hardware session reads the stand's real agreement before any fraction is trusted.

- **FM-135 A rigid fit from two references the same distance apart turns the plate by 90° with no residual.** A mislabelled pair of equidistant wells fits exactly: A1 at (0, 0) and A2 at (9000, 0), with A2 typed as `B1`, fit a rotation of 90.0° with a residual of 3e-13 µm and a scale error of 0, and put H12 at (63 000, 99 000) instead of (99 000, −63 000). The scale check and the residual both pass, so neither can see it (measured with a prototype while planning #19). *Check*: a bound on the fitted rotation (`MAX_ROTATION_DEG`, 10°, overridable per run up to 45°), checked after the fit and after the scale check; a test with two equidistant references is refused and, with the bound lifted, shows the exact 90° fit, which says why the bound exists; the mutant that widens the bound is killed. The hypothesis test draws the rotation within the bound, with margin: a draw near it, with jitter on a short baseline, lands beyond it and is rightly refused.

- **FM-139 Markup built from a result's text.** The report is a page attached to issues and opened in a browser on the microscope PC, and every word on it comes from a record that a person or a device named: the plate's and the objectives' names, the cell classes (the detector's own labels, or whatever a hand-edited `cells` result says), a route stop's name, every `assumed` line, the page's title and the `facts` the plugin passes. A label of `single"><b>` closes the `data-label` attribute of the dot paths and opens an element; a name of `<img src=x onerror=alert(1)>` in a tooltip is a script in a file that opens by double-click and travels attached to issues (#195). The same words used as an `id`, a class or a style would be the page's structure, not its text. *Check*: one function escapes (`html.escape(…, quote=True)`, which turns both kinds of quote into `&quot;` and `&#x27;`, so a value is safe in an attribute and in text); nothing from a record is an `id`, a class or a style (the ids are `w<k>`, the classes constants, the label colours a function of the label's *index*); a test puts markup and both quotes in **every** free-text field at once (`test_text_with_markup_is_escaped_wherever_it_is_shown`), counts the escaped text exactly (nine places, so a field that stops being escaped is a different count and not a pass), finds no element and no attribute the text did not write, and finds the page's classes and ids equal to those of a benign page; the mutant that drops the escape in one place (a tooltip, the title, a heading) is killed. A page that is meant to be read offline has no script, no `<link>`, no `url(`, and its only `href` are `#` fragments: the test asserts it of the whole page.
- **FM-140 An output bounded per unit but not in all.** The report caps the cells drawn in a well's panel (`max_cells_drawn_per_well`, at most 20 000), and 96 wells at that cap would be 1.9 million dots: about 30 MB even as one path per label and well (16 bytes a dot), against the 4.7 MB of the default of 2 000 (measured on the plan's prototype, which also measured 12.2 MB for the same page as one `<circle>` per cell, and 27.9 MB and 480 000 elements at 5 000 cells). The same shape is anywhere a limit is per item and the number of items is the caller's: a cap per well, per frame, per field, per label. *Check*: a bound on the total as well as on the unit, a share of it for each unit (`MAX_CELLS_DRAWN_TOTAL // wells`, so that the result is a pure function of the records), and the element count kept constant in the number of items (one path per label and well, never an element per cell); a test at the **largest cap the parameter allows, on the most units the test can build** (96 wells with 4 000 cells each at a cap of 20 000) finds the total at the bound and each unit at its share, and the mutant that drops the share is killed.
- **FM-153 A page audited as markup and never looked at.** The report's stylesheet says `svg { max-width: 100%; height: auto }` so that the maps and panels scale with their container, and the class swatches of its legend (`<svg viewBox="0 0 10 10">`, no `width`, no `height`) took the same rule: each was 1252 × 1252 px in a 1300 px window of Chrome, one full-width disc per cell class between the heading and the first panel, on every report. All the tests passed: the auditor reads tags and attributes, and the size lived in the stylesheet (review of #247). The same shape is any inline SVG, image or box whose size comes from a general rule (a viewBox says a ratio, not a size). *Check*: an SVG that is a glyph beside text carries a `width` and a `height` of its own and a more specific CSS rule in `em`, and a test reads **both** places (`test_a_class_swatch_has_a_size_of_its_own_so_it_cannot_fill_its_container`), because markup that parses and balances says nothing about what the stylesheet does to it; the mutant that drops either one is killed. A page that is the product is opened once in a browser before the PR, and the report says so (headless is enough: `--dump-dom` of a copy that has a script writing `getBoundingClientRect()` of the elements into the page, outside the repository).
- **FM-154 A value copied out of a record whose own state field says it is unreliable.** The route took a stop's `z_um` and `pfs_offset` from the scan frame nearest to it, and a frame carries a `focus` of its own: on an `unlocked` one the autofocus was on and searching, so its Z is wherever the search had got to and its offset is the stored one that nobody read locked on this sample (FM-118). The copy took the value and left the state behind, and the export would have handed both on as the operator's. The evidence is the adversarial review of #230, which found it; the first hit is the route's Z, fixed in #232. *Check*: a consumer that copies a measured value out of a record reads the record's quality state with it, and a record that is not usable is skipped, not used with a label; a test puts an unreliable record nearer than a reliable one and the mutant that ignores the state is killed (`test_z_comes_from_a_locked_frame_when_the_nearest_frame_is_unlocked`).
- **FM-189 A direction named in one frame and applied in another.** The plate page asks for a well's `left`, `right`, `top` and `bottom` walls. The operator named them as seen on Live, and `plate-registration` reads them in the stage frame (`left` is the centre minus half the width along stage X). On the Ti2-E the image content moves with the stage, so both axes came out reversed: a seed from one wall per axis put B3's centre 15.5 mm off on both axes, and a seed has no residual that could show it (Ti2-E session 2, #334; #327). *Check*: every side, arrow or direction a person names says which frame it is in, on the page and in the parameter's docs; the code maps it through what it knows (a calibration's rotation and mirror, or the image direction of a drive step), or refuses where nothing tells it; a test names the sides in the image frame on a stand whose image moves with the stage, and finds the centre where the walls are.
- **FM-190 A text generated from a value that its reader reads back as another value.** `smc presets save` writes each recorded parameter as the `key=value` text that `smc run --param` takes, and that reader spells "absent" as `null` for any field that admits `None`: a `str | None` `objective` that holds the string `null` is saved as `objective=null` and run later with no objective, and nothing says so (measured by #324's plan; `format_param` does not promise a read back, by design). The same shape is a number written without its type (`1` for `1.0`), a path whose backslash the reader takes for an escape, a list written as text where the reader wants JSON, a lone surrogate that `tomli-w` writes and `.encode("utf-8")` refuses (FM-05), and a subset of values that a cross-field rule refuses (`rows` without `columns`). *Check*: a generator reads its own output back through the reader that will read it, on the whole set and not pair by pair, and compares the result with the value it started from key by key; what does not round trip is left out and named (FM-107), never written; a test gives the one value that cannot (the string `null` in an optional field) and the round trip of every registered plugin's non-default values, and fails when a plugin or a field is added without a case (`test_the_round_trip_cases_cover_every_plugin_and_every_field_with_a_non_default_value`); the mutant that removes the read back is killed.

- **FM-207 A difference of two measurements, read as a property of the thing that changed between them.** `objective-offsets` (#380) gives an objective's offset as a well's centre under it minus the centre `plate-walls` recorded under another. If the plate moved as a whole in between (re-seated, bumped, drifted), every well shifts alike, the wells agree (a spread of 0.04 µm against a bound of 2 µm), the run ends `done`, and `--write` puts the plate's displacement into the profile as a property of the stand: a displacement of (+40, -25) µm came out as a 40X offset of (+2.50, -12.76) instead of (-37.5, +12.25), and the ±1000 µm bound lets it through (adversarial review of #380, reproduced on the demo stand with the plate record moved by that vector). The agreement of the wells is evidence that the shift is one translation, never that the translation is the objective's. The same shape is a calibration compared with a stale reference, a Z offset measured after the sample was refocused, and any "A minus B" where B was measured before something else could change. *Check*: the result says what the difference assumes did not change, in `assumed` and on the operator's page (here: `the plate has not moved since plate-walls registered it …`, and a line of the docs beside the step that registers it); where a second measurement of the reference is cheap, take it at the end and refuse a difference between the two (not done for #380: a step of m3 §20.6 that the design review decides); a test asserts that the line is in `assumed` (`test_the_samples_offsets_are_recovered_within_a_pixel`), and the mutant that drops it is killed.

## CI and its reports (ADR-0009)

Learned while building the light CI and the nightly's report (#353).

- **FM-192 A `-m` on the command line replaces the `-m` of `addopts`.** `addopts = "-ra -m 'not hardware'"` keeps the hardware tests out, and pytest takes the last `-m` it is given, so `pytest -m "not wallclock"` selects the hardware tests too. Measured at `d184703`, py3.13: `pytest --collect-only -q` collects 5 823 tests (71 deselected); with `-m "not wallclock"` it collects 5 894, the 71 hardware tests among them (`-m hardware` selects exactly 71). A marker expression added to the workflow for a speed-up becomes a run of every contract test against a stand that is not there. *Check*: every `-m` expression of `ci.yml` carries `not hardware`; `test_every_marker_expression_of_the_workflow_excludes_hardware` reads the workflow, and `test_a_marker_expression_without_not_hardware_is_found` shows the reader on a bad expression, so that the first cannot pass by finding nothing.
- **FM-193 A run that did not run, read as a verdict.** A cancelled or skipped job is neither green nor red. Read as "not a failure, so green" it closes the nightly's issue on a run whose tests never started; read as "not a success, so red" it makes `main` red when a push cancelled the older push run (`cancel-in-progress` on pushes to `main`, ADR-0009: the usual fate of the older of two close merges). *Check*: three states, `red` (a job failed), `green` (lint and tests both succeeded), `unknown` (anything else), and `unknown` touches no issue (`nightly_report.state`: `test_a_cancelled_or_skipped_run_is_neither_red_nor_green`, `test_an_unknown_state_touches_no_issue`); `point.red_main` lets the latest completed push run decide and skips runs that are in progress or cancelled (`test_a_cancelled_push_run_does_not_make_main_red`, `test_a_push_run_still_in_progress_does_not_decide`). The mutants that read "failure in either" as "lint failed", "both succeeded" as "either", and that let a cancelled run decide are killed. The aggregate is not the whole story either: on the demo dispatch of #353 four test jobs failed and one macOS job never got a runner (cancelled, no steps; the same runner starvation turned the push run of `main` at `d184703` red with every test green), and `needs.test.result` was `abandoned`, neither `failure` nor `cancelled`. A rule that read only the aggregate called it `unknown` and opened no issue. *Check*: when the aggregate is not a verdict, the jobs' own conclusions decide (`has_failed_job`: `failure` or `timed_out`, never `cancelled`): `test_a_matrix_abandoned_by_a_starved_runner_is_red_when_a_job_failed`, `test_an_abandoned_matrix_with_no_failed_job_touches_no_issue`.
- **FM-194 A report file parsed all or nothing.** A JUnit file cut while pytest wrote it, or with a syntax error in the middle, fails the parse as a whole; a reader that skips the file hides the failures it recorded before the error, and a job whose process aborted (FM-179) leaves no file at all. `XMLPullParser.feed` queues a syntax error and `read_events` raises it only after it has yielded the events that came before it (measured on Python 3.13), so the failures before the error are there to be read. *Check*: what was read before the error counts and the file is named as unreadable, so that nobody reads the list as complete; the failed jobs come from the jobs' own conclusions as well, so that a job with no file is named (`test_a_truncated_junit_file_does_not_hide_the_failure`, `test_a_syntax_error_after_a_failure_does_not_hide_it_either`, `test_a_failed_job_without_a_junit_file_is_named_with_its_conclusion`); the mutants that never drain the parser or never close it are killed.

## Concurrency (the layer's own locks and threads)

Learned from the design review of #59, where `/code-review` reproduced 15
races in the first motion guard.

- **FM-60 A motion found by name.** A waiter or a stop looks up "the" motion of a device by its label, and finds another caller's or none. A stop is lost, a stopped move reports an arrival, a stale waiter stops a new move. *Check*: only the action that sent a command waits for it, holding the lock; a stop is a per-device generation the action compares, not a flag on whatever registration exists (design §13).
- **FM-61 A give-up by a bystander.** A thread that only waits for someone else's motion stops it when its own short deadline passes. *Check*: only the thread that started a motion stops it when giving up.
- **FM-62 Log before stop.** A stop path that writes its log line first is delayed by a blocked console (a QuickEdit selection on Windows), or skipped by a second Ctrl-C. A step between the stop and its log line (a busy check, a registry update) that is interrupted skips the line too, so the log never shows a stop that was sent (adversarial review of #59's third round). A path that sends several stops in a row and logs each one as it goes holds the next stop behind the previous line: the emergency stop did, Z behind XY (#76). *Check*: send the stop, then log, and write the line in a `finally` around whatever runs in between; several stops in a row are all sent before the first of their lines; an interrupt in one of several stops in a row is held until the later ones are sent, then re-raised (`Executor._stop_linked`, `MMAutofocus._on_z_stop`, #166).
- **FM-63 A readback in its own lock section.** Another caller acts between the end of the wait and the readback, so the move returns another move's position and a set returns another thread's value. *Check*: command, wait and readback in one lock section.
- **FM-64 A halt that can be caught as a refusal.** `except SafetyRefusedError: skip` swallows the emergency stop, and the loop carries on. *Check*: the halt error derives from no error that a tool is expected to catch and carry on after, and a halt since the call is checked before every other refusal on every path an action takes: the lock wait, re-entry and the section itself (#80).
- **FM-65 An interrupt between `acquire()` and `try`.** A Python-level lock wrapper (a generator context manager) leaves a window in which a Ctrl-C keeps the lock held for good; `with lock:` has none. *Check*: nothing between `acquire()` returning and the `try`; a test interrupts the main thread (`_thread.interrupt_main()`) while it waits for the lock.
- **FM-66 A check that is not the last one.** A halt (or any flag set without the lock) checked before a slow step, such as the guard polling a serial device, lets the action run after the flag was set. Bookkeeping added between the last check and the command reopens the window: recording what the action waits for did (adversarial review of #68). *Check*: check the flag again immediately before the command, after any bookkeeping.
- **FM-67 One caller's outcome kept under a shared key.** A record of how a caller's operation ended (a stopped `wait=False` move) is keyed by the device alone, so another caller's new operation on that device erases or replaces it, and the first caller's later `wait()` reports on the other move and misses its own stop (adversarial review of #59's fix round). *Check*: key per-caller state by caller and resource; a test has a second thread act on the same device before the first one asks how its operation ended.
- **FM-68 A give-up before the command.** The path that stops a motion when its action fails also runs for an interrupt that lands before the command was sent. It stops a stage that nobody commanded, or logs that a turret "cannot be stopped from smc" (adversarial review of #68). *Check*: an action gives up only from the point where its command may have reached the device; a test interrupts it just before the command and sees no stop and no give-up line.
- **FM-69 A teardown from inside the action it tears down.** `close()` called on the thread that is inside an action (a Ctrl-C handler that runs during a move's wait, a callback inside a snap) re-enters the `RLock` and unloads the devices; the action then touches a device that no longer exists and raises a bare `RuntimeError` from MMCore instead of a `HardwareError` (adversarial review of #8). *Check*: a teardown that finds the lock already held by its own thread stops what moves, releases nothing and raises, so the caller closes again once the action has returned; a test calls it from inside a stub's busy poll.
- **FM-89 A sequence of actions whose steps record their own call.** A compound (suspend the autofocus, move Z, engage it again) runs several actions in one lock section. Each nested action recorded its stop generation when it was itself called, after the compound had waited for the lock and run the steps before it. A `ZStage.stop()` pressed while the Z move queued, or during the suspend, was therefore lost and the move was sent; a `disengage()` during the move was undone by the relock, so PFS ended on after a switch-off that reported success (adversarial review of #13). *Check*: the sequence records the stop generations and the halt mark when it is called, before it waits for the lock, and every nested action compares with those; a test stops the device while the sequence waits for the lock, and between two of its steps, and finds nothing sent after the stop; another sends the safe call during the main step and finds no restore.
- **FM-91 A stop that misses a motion moving its axis or the stand.** Stops are keyed by device: a stop reaches the actions keyed by its device's label, and the emergency stop reaches the devices on its list. A motion keyed otherwise is missed. PFS locking again, or following its offset, drives Z under keys of its own (`PFS`, `PFSOffset`), so a `ZStage.stop()` during the relock was ignored and PFS searched on for up to `lock_timeout_s`. The offset device, a role with no capability, was not on the emergency stop's list, although `moving()` reported its move, which then held the lock until its timeout (review of #140). A motion about to start counts too: a Z stop that landed while a locked `focus_by_um` read its offset's anchor switched PFS off but let the offset move go out after it, because the link stopped the offset device only once `moving()` named it (adversarial review of #140's fix round). *Check*: for every motion the layer can wait for or register, name the stops that must end it: its own, the stop of the axis it drives, the emergency stop and `close()`. Such a stop also cancels the motion's command when it is not sent yet. A test runs each motion in another thread, sends each such stop, and finds the motion's stop in the fake's log, its action raising `MotionStoppedError`, and nothing left in `moving()`; another sends the stop just before the command and finds no command in the log.
- **FM-97 A linked stop's outcome read before it has run.** `Executor.stop` marks a link as reached when it takes its snapshot, before it calls the linked stop. The action whose block ends meanwhile reads "a stop reached me, and nothing failed", and reports PFS "left off" while the switch-off is still on its way. When that switch-off then fails, PFS is on and the tool was told otherwise; the "may still move Z" WARNING is never written. Measured with a switch-off that takes 0.4 s and then fails: "left off" at 159 ms, the failure at 565 ms, PFS on at the end (adversarial review of #144; the window dates from #140, and #144 makes it reachable from `engage()` and the offset moves). *Check*: an action that reads the outcome of a stop another thread runs waits, bounded, for that stop to finish before it reports; a test makes the linked stop slow and failing and finds no "left off" claim. The wait is bounded (`Z_STOP_OUTCOME_WAIT_S`, since the waiter holds the microscope lock), and a stop that has not returned by then is reported as a failure ("may still move Z"), never as done (#158). It waits for the one step whose outcome it reports (the switch-off), not for the whole linked stop: a slow offset stop after a switch-off that worked was reported as "could not be switched off". A halt or an interrupt does not wait, and goes on at once with what is known (adversarial review of #158): one that ends the action, and one that comes during the wait (the halt is read from the stand's halted state, the exception that ended the block being the Z stop's own `MotionStoppedError`); an interrupt in the wait logs what is known, as one that ended the action (#166).
- **FM-70 A plain lock on a path a signal handler re-enters.** Python runs a signal handler on the main thread between two bytecodes, so a Ctrl-C handler that calls `stop()` or `close()` can run while that same thread holds any lock the stop path takes. A `threading.Lock` then blocks for ever and sends no stop: the facade's capability cache did, when the handler landed inside `has()` (design review of #8). `Executor._registry_lock`, which `halt()` takes, was one too; #76 makes it an `RLock`. Re-entry has its own trap: the handler runs at any point of the section it interrupted, even inside one statement, so a section that iterates the registry, or checks an entry and then deletes it, finds it changed. *Check*: every lock the stop and close paths take is an `RLock`, or they take none, and a lock hidden in a primitive counts (`threading.Event.set()` takes a plain `Lock`: a flag the stop path sets is a plain store, adversarial review of #158); every section under such a lock stays correct if a stop runs at any point inside it (iterate a snapshot taken in one call); a test runs the stop from inside the locked section, in a thread with a join timeout (FM-44). A call added in front of a release is a new place for a second Ctrl-C to skip it: `Microscope.__exit__` read `moving()` before `close()`, and an interrupt there left the stand held (adversarial review of #224); the read goes inside a `try` whose `finally` is the release, and a test interrupts the read.
- **FM-168 A one-shot flag set after the call it guards.** `Executor._move` set `gave_up` once the timeout's give-up had returned, so a second Ctrl-C *inside* that give-up reached the outer `except BaseException` with the flag still down, and the motion was given up on a second time: two `stop()` sent, and the second one's note (`accepted`) hid that the first was cut (#224, measured on a `FakeCore`). A flag that keeps a path from running twice has to be up before an interrupt can cut the call, and the cut has to say what it left undone, since a flag alone turns "ran twice" into "ran once, cut, and nothing says so": the Ctrl-C line would read "no move was under way" over a move whose stop was cut. *The flag is not set at the top, either* (the adversarial review of #224, reproduced): set before the give-up registered the motion, it left a window in which a Ctrl-C meant no stop was sent and nothing was tracked, so `close()`, which stops only what is tracked, could not retry, where the old code gave up again. *Check*: the flag goes up where the retry becomes real, in the give-up's `registered` callback, right after the motion is tracked; before that the `except` gives up again, after it `close()`, which every command runs on leaving its `with`, is the retry; the `try`/`except` that notes `interrupted` is inline at the call, so that its set-up is covered too, and it re-raises with a bare `raise`, keeping nothing (FM-98); tests cut the stop with a Ctrl-C raised by the device call (an instance attribute of the fake, removed with `del`) and count what was sent before the stand closes (once), cut the registration itself (the stop is sent once, by the give-up that ran again), and cut the call as it is entered (a trace function raising at the `call` event stands in for a signal handler) and read the note on the exception that escapes; the mutants that set the flag at the top of the branch, never set it, or drop the note are killed.
- **FM-93 A holder that still waits for a motion it gave up on.** While the give-up sends the stop, checks busy and writes its line, the holder still records "waiting for" the motion, so a queued action is refused or run depending on how long those take; a slow log handler made a queued move fail (#101). *Check*: once a give-up has registered its motion, the holder stops recording "waiting for" it before any device call or log line; a test has a contender poll the lock during the give-up (FM-44: an event, not a sleep).
- **FM-184 An unload during an unlocked read.** The facade's reads (`state()`, the light's and the turret's, a capture's position, STOP) take no lock, by design (FM-70), so `close()` cannot see them: `unloadAllDevices` ran while a status tick was inside the core, and STOP pressed during a Disconnect reached devices that had just been unloaded (#305, reproduced on `FakeCore`: the core listed only `Core` while the read was still inside it). *Check*: the page registers each of its reads (`_Reading`: a token added to a set **before** the facade is taken, no lock), and a Disconnect or `release()` drops the facade first, then waits, bounded (FM-15), for the set to empty; STOP registers and never waits. A test holds a read in flight on an `Event`, waits until the facade is dropped, and finds the devices still loaded until the read ends; a mutant per read deletes its `with`, and one per read moves the *device* call (`state`, `is_on`, `labels`, `position_um`) out of it while the lookup before it stays in: the registration test probes the device call, never the lookup (the first version did, and five such mutants survived).
- **FM-187 A wait added between letting go of a resource and releasing it.** `release()` dropped the facade from the page and then waited, bounded, for the reads in flight (#305); the local variable was the only reference left. A second Ctrl-C landing in that wait (it is the main thread's, and a sliced sleep is interruptible, FM-83) left the stand neither held nor unloaded, and a second `release()` found nothing: the vendor drivers stayed held until the process died. Before the wait, nothing sat between the drop and the close. Two reviewers found it independently. *Check*: the drop, the waits and the release are one `try`, and the release is its `finally` (a Ctrl-C before the drop finds the page still holding it, so the `finally` drops again); a test makes each wait raise `KeyboardInterrupt` and finds the devices unloaded and the interrupt not swallowed, and a mutant that releases only on the normal path fails it.

## A server and a view (the plate page)

Learned while planning and building the plate page (#197), on Panel 1.9.4 and 1.10.0.

- **FM-143 A server that swallows the operator's Ctrl-C.** A blocking `panel.serve` returns normally on Ctrl-C (Bokeh installs its own SIGINT handler): no `KeyboardInterrupt` reaches the caller, the command exits 0, and nothing says that the operator interrupted, so a run going on and the stand's release are handled as for a server that simply ended (measured, POSIX; Windows not measured). *Check*: the server runs in a thread (`threaded=True`) and the main thread waits in slices of 0.1 s (also what lets Ctrl-C through on Windows, FM-83), where the `KeyboardInterrupt` is the command's own; the first one stops the server, a second one during the wait for a run is the CLI wrapper's (exit 130, FM-71); a test raises the interrupt from a stand-in thread (FM-44), never a signal.
